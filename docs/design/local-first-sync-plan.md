# NeuInk 账号与本地优先同步实施方案

日期：2026-11-08。代码参考：`929f504`。

状态：用户已确认，在 alpha 实施中；本文是目标设计，不表示所有能力已经实现。本文扩展[本地优先同步评估](../references/neuink-local-first-sync-assessment.md)，当前完成项与未完成项见[开发计划](../development/dev-plan.md)。已在 Ubuntu 隔离环境验证 Java 服务和 PostgreSQL；尚未测试跨校园 Wi-Fi 或桌面双向资料同步，测试不使用日常资料。

## 1. 首期目标与明确取舍

- 保留无账号的完整本地模式。账号只控制同步服务，不成为本地阅读、编辑、AI 调用的必备条件。
- 支持多个独立用户，每个用户拥有私有资料库；同一用户可在多个设备间同步。首期不做用户之间共享、团队协作或同时共同编辑。
- 服务器临时放在校园局域网，单实例部署，无 CDN、无独立消息队列、无 Redis、无 Kubernetes；PDF 和图片存服务器磁盘。
- 采用独立开源客户端同步模块与服务端，同一协议用于校园、自部署和未来官方托管。校园连接工具是可替换的部署选择，不写死在业务协议里。
- 首期服务端可读内容（HTTPS 传输、主机磁盘及备份保护），不宣传端到端加密。API Key 不同步。未来端到端加密会影响服务端合并/检索/恢复，不能视作无成本追加。
- 默认服务器能持续联网，管理员能安装服务；建议 Linux + Docker Compose。如果实际是 Windows 主机，先验证运行方式、常驻、磁盘权限和防火墙，不预设已经具备 Linux 环境。

## 2. 校园网连接方案

### 2.1 先区分问题

不同 Wi-Fi 网段并不必然不可达，同一 SSID 也不保证互通。需区分跨 VLAN 路由/ACL、无线客户端隔离、服务器监听/主机防火墙、DHCP 地址变化、校园认证门户、DNS/TLS 和服务自身故障。

诊断必须针对实际 HTTPS TCP 端口和应用探测，而不能只看 ping。客户端给出“服务器不可达”“证书不受信任”“登录失效”“服务未就绪”“网络可能需要认证”的不同状态；不将网络失败全部解释为密码错误，不因暂时离线清空账号和队列。

### 2.2 推荐默认：Tailscale 私有通路 + NeuInk 独立账号

临时小规模试用，服务器和测试客户端安装 Tailscale，通过固定的覆盖网络域名访问服务器。优先直连，无法直连时可能通过 DERP 中继；具体能否建立连接取决于校园出口对协调服务/中继的可达性。

部署选择：服务器宿主机运行 Tailscale；Compose 的应用端口仅映射到宿主 `127.0.0.1`；由 Tailscale Serve 提供 tailnet 内的 HTTPS 入口。数据库只在 Compose 内部网络暴露。此模式不再强制额外部署 Caddy，也不使用面向公网的 Funnel。

Tailscale 身份用于加入网络，NeuInk 用户名/密码用于访问资料。网络层获准不等于获得资料访问权。收紧覆盖网络访问规则，仅允许客户端到同步入口，不将服务器全部端口/整个校园子网开放。

这是依赖外部协调服务的实用方案，不是全套基础设施完全自托管。附件最终存本地服务器，但无法直连时加密流量可能经过第三方中继。不能承诺任意校园网络必通，也不在产品中承诺某商业计划永久免费或无人数限制。

### 2.3 局域网直连与完全自托管备选

| 条件 | 路径 | 限制 |
| --- | --- | --- |
| 客户端和服务器确实互通 | 稳定内网地址/DNS + Caddy HTTPS | IP 变化要处理；内网 CA 的根证书须在客户端正确受信任 |
| 各网段隔离，但客户端与服务器都可访问外网 | 优先覆盖网络 | 直连失败可能中继，附件速度需实测 |
| 要完全自建协调/中继 | Headscale + 必要的可达 DERP，或学校提供的 VPN | 协调和中继必须处于各客户端可达的位置；仅放在同一被隔离内网无法解决隔离 |
| 不允许安装覆盖网络客户端 | 学校分配可路由服务地址，或经批准的公网反向隧道入口 | 后者通常需公网入口和持续隧道，不能再声称没有外部设施 |
| 出口和内网访问都被阻断 | 先解决网络接入条件 | 应用继续离线工作，等待恢复；业务代码不能凭空创建网络通路 |

Headscale 不是本项目首期默认部署依赖。若要所有网络基础设施也自托管，需要额外可达主机/域名和维护中继，工作量应独立估算。具体事实与官方来源见[校园网络研究](../references/campus-sync-network-research.md)。

### 2.4 HTTPS、地址与服务器身份

- 覆盖网络默认用 Serve 提供的 HTTPS 名称；普通内网模式用 Caddy 终止 HTTPS，私有 CA 正确导入实际 HTTP 客户端的信任库。当前 Rust reqwest/rustls 的根证书加载策略要验证，不能假定浏览器信任就等于 Rust 客户端信任。
- 不以关闭证书验证作为解决办法。Caddy 私有 CA 不会自动被其他电脑信任。[Caddy 官方说明](https://caddyserver.com/docs/automatic-https)
- 每台同步部署有固定 `server_instance_id`，绑定关系为 server + account + library；改 IP/域名不重建资料库。该 ID 用于防误绑定，不能替代 TLS 身份校验。
- 首期一个主地址即可；以后可配置经过用户确认且指向同一部署的备用地址。只在验证来源后使用，不跨未知来源转发登录令牌，不自动跟随携带凭据的跨域重定向。
- 提供只含版本、能力与服务身份的公开发现接口。账号和论文列表必须鉴权。

## 3. 单机服务端组织

```text
桌面客户端：本地保存 + 持久同步队列 + 安全凭据
                       |
                 HTTPS 私有入口
          Tailscale Serve 或 Caddy（二选一）
                       |
              neuink-server（Java/Spring Boot）
                 /                 \
          PostgreSQL             附件持久卷
       账号、权限、对象版本       PDF、图片、解析包
       删除记录、变更流          暂存上传、不可变 blob
```

按用户确认改用 Java 21 + Spring Boot 3.5、JDBC/HikariCP、Flyway 和 PostgreSQL，保持 auth、libraries、sync、blobs、admin 的单体职责划分。Java 服务统一在 `apps/server`，桌面与本地同步仍使用 Rust。旧 Rust 后端已移出 Cargo workspace 并保留本地恢复备份。Java 已验证新建数据库迁移；已有 SQLx 数据库迁移尚未验证，不启用自动 baseline 跳过检查。

首期 Compose 为应用 + PostgreSQL；直接内网 HTTPS 模式另加 Caddy。目录例如 `/srv/neuink/{postgres,blobs,uploads,backups}`，名字仅为部署建议，不操作当前 D 盘资料。备份最终必须复制到其他磁盘/主机；同盘 backups 只是暂存，不算独立灾备。

数据库只保存结构化内容、状态和文件清单，不将大 PDF 作为数据库字段。附件通过鉴权接口流式读写，不暴露可枚举的静态目录。初期本地磁盘存储，未来可替换为对象存储，不改变客户端协议。磁盘空间、账号配额、请求大小和并发上传上限都由后端执行。

## 4. 账号系统

### 4.1 用户能力

- 首次部署通过服务器控制台创建管理员，无默认密码，不允许互联网“第一个注册者自动管理员”。
- 默认关闭公开注册，管理员生成有期限、限次数的邀请码；用户在 NeuInk 内设置用户名和密码注册。邮箱可选，首期不依赖 SMTP。
- 用户可登录、退出、改密码、查看当前设备/其他设备、撤销设备登录、查看资料库和用量。
- 忘记密码：管理员线下核对后签发短期一次性重置凭证；不读取旧密码，不通过普通日志传递凭证。启用邮箱验证和自助找回留作后续。
- 管理员可邀请/禁用账号、调整配额、撤销会话、查看服务健康和审计；账号管理权限不默认授予应用内阅读所有私有资料的权限。但服务器运维有磁盘/数据库访问能力，首版不具备抵抗服务器管理员读取内容的端到端加密。

### 4.2 密码与登录态

- 密码使用成熟库实现 Argon2id 加随机盐，参数按服务器性能基准设定并保存参数版本，不使用普通 SHA/hash 保存密码。[OWASP 密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- 用户名规范化及唯一约束、登录限速、失败返回避免枚举、管理员高风险操作重新验证身份；校园 NAT 下不能只按公网 IP 限流到误伤整个校园，要结合账号与 IP。
- 推荐短期随机 opaque access token + 每设备 refresh session，服务端保存 token 摘要，不保存可直接使用的明文令牌。不需要第一版引入 JWT 和完整外部 OIDC 服务。
- access token 候选有效期 15 分钟；refresh 候选闲置 30 天、最长 90 天，均为可配置初始值，需测试后确定。每次刷新轮换，支持重放检测与设备撤销；修改密码、禁用账号后废止相应会话。前端/后端刷新单飞并考虑响应丢失的幂等重试，避免弱网导致正常设备反复被误判盗用。[OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)
- refresh token 保存在操作系统凭据库，access token 在 Rust 进程内存使用，React/localStorage 不持有长期令牌。沿用现有 keyring 能力；不能将令牌写进可同步 settings、资料目录、日志或备份清单。
- 本地阅读不需要检查登录态；令牌失效只暂停云同步。退出默认保留已下载资料，另提供明确确认的“移除本机副本”；设备吊销只能阻止后续服务访问，不能远程收回已经离线下载的文件。

### 4.3 资料隔离与账号切换

每个请求由服务端登录态确定 user_id，查询再验证 library owner，不信任客户端提交的 owner_id。附件下载/Range/上传状态同样校验，不允许知道 hash 或对象 ID 就能访问别人的文件。[OWASP 授权](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)

一个本地资料库只绑定一组 server/account/library。首次绑定前预览内容与同步范围。切换账号必须暂停旧队列和传输，执行未保存内容保护，不自动把账号 A 的资料上传给 B；新账号选择自己的本地资料库，或显式创建副本再导入。现有 `portable/data` 不因加账号自动迁移、清空或重映射。

## 5. 数据表与 API 草案

| 数据组 | 表/职责 |
| --- | --- |
| 账号 | users、credentials、invites、password_reset_tokens |
| 设备与会话 | devices、sessions、refresh_tokens；撤销、到期、设备标识 |
| 资料库 | libraries：owner、schema、当前修订、配额；首期只有 owner |
| 内容 | objects、object_versions：对象类型/ID/内容/修订/删除状态 |
| 增量与重试 | change_log、applied_operations、device_checkpoints |
| 文件 | blobs、object_blob_refs、upload_sessions；归属、hash、大小、完成状态 |
| 管理 | audit_events：登录、邀请、撤销、配额和恢复，不记录正文/密码/token |

核心请求面建议如下（非已实现接口）：

- `GET /.well-known/neuink-sync`：实例身份、协议版本、能力、上传限制。
- `/v1/auth/register|login|refresh|logout|password|reset`：认证；注册必须邀请码。
- `/v1/me`、`/v1/devices`：当前账号、设备列表和撤销。
- `/v1/libraries`：创建、列出有权访问的库，返回绑定信息。
- `/v1/libraries/{id}/changes?cursor=...`：分页变化与删除记录。
- `/v1/libraries/{id}/operations`：携带 operation_id/base_revision 提交对象操作。
- `/v1/libraries/{id}/objects/{objectId}/versions`：取历史/冲突比较所需版本。
- `/v1/libraries/{id}/uploads`、`.../uploads/{id}`、`.../complete`：建立上传、续传与确认。
- `/v1/libraries/{id}/blobs/{id}`：鉴权下载，支持 Range。
- `/v1/admin/*`：账号/邀请/配额；首期管理 CLI 覆盖相同业务入口，避免先开发完整管理网站。

服务端用事务内的库修订分配和条件写保障并发：例如先锁定 library 行，再推进 revision 并写对象、change_log、幂等结果。不能直接用可能乱序提交的自增 ID 当“永远不会漏项”的游标。重复 operation_id 且内容相同返回原结果，不同内容则拒绝。每个逻辑操作原子成功或失败；批次逐项返回，客户端只推进已安全处理的范围。

## 6. 同步算法与附件协议

保留上次评估的实体化、基线、冲突、删除和解析版本原则。增加账号绑定后，客户端队列按 server/account/library 隔离。

1. 本地操作通过 workspace 的可恢复事务保存内容及变更意图。SQLite 同步状态库保存 outbox/基线/游标，文件与 SQLite 的跨存储提交必须有 journal 恢复，而非假设单次 SQL 事务同时保护文件。
2. 同步检查连接/授权/协议版本，拉取变化；保存同步基线，合并本地已保存内容；编辑器 dirty 时保留草稿，不覆盖。
3. 无冲突的操作携带 base_revision 上传；服务端检查归属和版本，在一个事务内记录结果。
4. 单个对象冲突不阻塞无依赖对象；依赖对象等待。收到远端更新不能再次生成相同 outbox 导致循环。
5. 删除/恢复作为显式状态同步。回收站物理清理不立刻清除服务端删除记录；长期离线设备游标过期后强制重新建立基线，防止复活已删除内容。

附件使用不可变内容和清单，分块上传/续传、流式校验 hash，服务端确认完整后允许发布引用。配额在建立上传时预留、完成时结算，过期上传释放；文件哈希去重只在同一用户或库内，不能跨租户泄露文件存在性。服务器落盘完成但数据库登记失败的孤儿 blob 延后清理；不能先发布元数据再假装附件已经成功。

客户端可先同步条目并显示“附件待下载”，但新解析快照及其引用要按逻辑版本一起应用。已完成译文/详略同步，运行任务/模型密钥/执行授权不随内容传播。来源依赖的规范化解析结果不能在另一端任意重解析代替。

暂不需要 WebSocket：启动、保存后防抖、网络恢复、手动触发和有界周期拉取已能形成闭环。候选参数为保存后 3 秒合并调度、在线每 60 秒检查、失败指数退避到 5 分钟并带随机抖动，最终按实际数据量调优。上传有独立并发上限，笔记等小对象优先于大 PDF。暂停只暂停同步，不暂停本地保存。

## 7. UI 与交互

设置新增“账号与同步”，保持现有阅读界面：

- 服务器地址及测试连接；显示部署名称、协议是否兼容，不要求用户理解网段。
- 当前账号、登录/注册、退出、设备管理。
- 当前资料库绑定、同步范围、附件下载策略、占用容量。
- 自动同步开关、立即同步、暂停/恢复、同步任务与冲突入口。

首次流程：填地址 → 测试连接 → 邀请注册/登录 → 选择新云端库或已有库 → 预览本地上传/远端下载范围 → 确认同步。两份既有库不自动整库覆盖，先做身份/重复项检查。

常驻轻量状态区分“本地已保存”“等待联网同步”“正在同步”“有冲突”“登录失效”“附件未下载”。接入现有全局任务/通知，支持逐项重试、暂停、取消；进度分别展示对象数和附件字节，不用一个虚假的总体百分比。网络反复波动合并通知，不每次弹错误。

状态由 Rust 同步协调器持有，前端 hook 订阅；任务展示复用现有组件。设置区拥有自己的滚动，冲突对话框保持独立滚动/焦点；不抢阅读器快捷键和拖动。暂不把登录或冲突弹窗强制覆盖整个阅读流程。新增 UI 无须额外 UI 框架。

## 8. 部署、运维与后续迁移

- 固定依赖/镜像版本，提供 Compose、配置模板、数据库迁移、建管理员 CLI、备份与恢复命令。应用容器不以 root 写用户卷；数据库不发布校园网端口。
- 提供最小存活探测与受控就绪探测，监控磁盘剩余量、数据库可用性、同步错误和积压；日志不含论文正文、密码、令牌。
- 日常备份覆盖数据库、附件、服务实例身份和必要配置。`pg_dump` 能提供数据库一致快照，但它不保证外部附件目录与数据库自动同时一致。初期备份进入短暂维护模式暂停写入/GC，完成数据库及匹配附件清单备份并校验，然后恢复；客户端继续本地工作。[PostgreSQL 备份](https://www.postgresql.org/docs/current/backup-dump.html)
- 定期在隔离目录实际恢复验证。不要对运行中的数据库目录直接打 ZIP 当作可靠备份。
- 恢复到旧备份时递增 sync_epoch，使客户端重新核对基线及本地未上传变更，避免旧服务器游标被误认为最新状态；恢复流程单独测试删除传播和本地新内容保留。
- 正常迁到新主机时保留实例/账号/库/对象 ID，复制数据库和文件、校验、切换稳定域名并关闭旧写入口，避免双主。更换内容存储只替换后端实现，CDN 不是迁移必需条件。
- 开源仓库保留客户端/服务端/协议与自部署文档；提供导出与搬迁途径。覆盖网络、身份提供方和未来对象存储的第三方许可证、使用条件在引入前单独核验。

| 路径 | 工作 |
| --- | --- |
| `crates/neuink-domain` | 稳定身份、纯冲突规则，保持无网络/文件依赖 |
| `crates/neuink-workspace` | 统一写入口、实体读取/应用、持久事务、删除标记、外部修改检测 |
| `crates/neuink-sync-protocol`（新增） | 客户端/服务端共享 DTO、版本、错误码；不依赖 Tauri |
| `crates/neuink-sync`（新增） | Rust 同步状态机、outbox/游标、HTTP、会话与附件重试；在 Tauri 生命周期中调度 |
| `apps/server`（新增 Rust 可执行程序） | Axum、认证授权、PostgreSQL、附件、管理 CLI |
| `crates/neuink-config` | 用户偏好、设备连接配置、凭据引用分离；旧 LLM 明文 Key 安全迁移 |
| `crates/neuink-ipc` | 同步/账号命令与事件，收拢对话等直接写点；长期令牌不暴露前端 |
| `apps/desktop/src/modules/settings` / shared IPC | 账号与同步设置、首次绑定、冲突和任务展示 |
| `deploy/server`（新增） | Compose、配置模板、网络两种模式、升级/备份/恢复手册 |

不把服务端接入现有 Tauri command 直接复用；服务端独立执行鉴权和输入校验。共享领域规则，不共享桌面路径、OS 权限或运行中状态。

## 10. 阶段与验收门槛

| 阶段 | 交付内容 | 通过条件 |
| --- | --- | --- |
| P0 网络验证 | 一台实际校园服务器，两台不同网络客户端，受保护 HTTPS 测试入口 | 校园不同 Wi-Fi/热点切换；能区分直连、中继、不可达；服务身份/TLS 有效；实测大文件吞吐 |
| P1 后端账号 | Compose、邀请注册、登录刷新、设备撤销、库归属、额度 | 两账号互不能读写/下载；密码重置/撤销有效；并发刷新、超时重试和限流可恢复 |
| P2 本地同步内核 | ID、事务/outbox、笔记/条目/标签/批注增量 | 双端离线修改、删除对编辑、崩溃恢复、外部编辑、账号切换均不丢文、不串账号 |
| P3 阅读成果与 UI | PDF/图片/解析、译文/详略、卡片构思；全局任务、冲突处理 | 按需下载、断点续传、磁盘满/配额不足、附件缺失、旧 schema、取消重试正确；不自动重跑 AI |
| P4 beta 稳定性 | 真实网络与原生 Tauri 验收、备份恢复、升级迁移 | 换 Wi-Fi/休眠/认证失效/服务器重启仍可本地保存；恢复旧备份不吞本地新内容；冲突可解决 |

开发在 alpha；确认范围和验证结果后晋级 beta，稳定后经用户确认再进 main。不能以服务可启动代替同步正确性，不能用模拟测试通过代替校园真实网络可达性。部署前还需确认服务器 OS、可管理权限、常驻出网条件、客户端能否安装覆盖网络；这些决定部署模式，不改变账号及同步核心协议。
