# 校园旅行：海豹伙伴彩蛋

## 定位

替代原校园漫游／种地方案。保留阅读器原有信息密度和主题，游戏作为独立按需加载的拟物小彩蛋，沿用活动栏与工作区页签。它在普通主题也可打开，但材质仅限游戏内部；不把整个阅读器替换成游戏 UI。

## 参考与取舍

查阅日期：2026-09-28。依据 Hit-Point 的[官方商店介绍](https://play.google.com/store/apps/details?hl=ja&id=jp.co.hit_point.tabikaeru)与[官方 FAQ](https://www.hit-point.co.jp/games/tabikaeru/faq/faq.html)。

《旅行青蛙》的基础循环是收集三叶草、购买物品、准备行囊，随后角色自行出发，等待旅行照片和各地纪念物。FAQ 补充了便当／护身符影响旅行、居家停留和旅行时长有变化、照片和土产并非每次保证获得，以及抽奖券与商店。

设计判断：有趣的是“轻干预、等待惊喜、角色有自己的生活、收集记忆”，不是每时每刻盯着倒计时。我们采用这些体验原则，但不照搬 IP、游戏素材或经济系统。

| 内容 | 我们的取舍 |
| --- | --- |
| 主角独立旅行 | 用户点击出发，不需操纵地图移动 |
| 行囊 | 三种免费随身物，改变信件和纪念物，不阻止一键出发 |
| 照片与相册 | 每次寄信，收藏去重；真实路线先用文字明信片，补图后接入场景 |
| 角色陪伴 | 立体海豹待机／挥鳍／蹦跳／打盹／看窗外／使用笔记本，出门后角色隐藏 |
| 长期成长 | 旅行次数、纪念物、地点印章；社团、食堂、访客以后另行设计 |
| 货币、商店、抽奖、广告 | 首版不加入，避免阅读工具变成刷资源任务 |
| 论文结合 | 不读取正文，不伪造读完统计；未来阅读奖励只能是可选纪念，不是出游门票 |

## 交互与首版边界

宿舍 → 点击“去逛逛” → 出门中 → 途中收到来信 → 收藏照片 → 按时归来。

首程 60 秒、30 秒来信，方便体验闭环；后续校园散步 5 分钟、信息学馆 10 分钟、小南湖 15 分钟、一号教学楼 12 分钟，均半程来信。时长是游戏节奏，不是实际步行耗时。点击“去逛逛”先选择地点，再明确出发；游戏内旅行册在出门时可查看但不能重开旅程。

三个校园地点各有 3 段轮换故事及纪念物，与行囊文案组合。路线和行囊随出发快照保存，不被后续设置改变；地点印章仅在归来后从旅程推导。来信是预设虚构故事，不读取论文或实时天气。实际照片尚缺：真实地点用文字明信片留位，体验散步保留明确标注的插画，不将其冒充校园建筑。需求见 [图片清单](campus-travel-assets.md)。

场景采用二维绘画的 2.5D 透视，不使用三维模型。Canvas 2D 依次合成底层四季窗景及天气、带透明窗洞的室内画稿、椅子上的海豹、遮挡身体下部的原桌面、面向海豹的电脑。窄屏只调整取景，不移动角色与家具的相对位置。海豹默认完全静止；点击后关键帧播放一次（1.4–5.4 秒），完成回到发呆，失焦／隐藏暂停，天气刷新不重启动作。天气有独立时钟，晴天静止状态不保持帧循环。无相机拖动，不截获工作区手势。

游戏不再导入 Three.js，原 sealRig 三维海豹和电脑构造代码已删除，其他模块的 Three.js 不受影响。Button、Input、Dialog 保留原语义、焦点与键盘契约。新增图片由 imagegen 内置工具生成，透明拆件与手绘电脑保留原 alpha，原宿舍相机与肩带移除以留出电脑桌面；旧原图仍保留。提示词和文件映射见 assets/cutout-generation-spec.json，原控件素材见 animated-generation-spec.json。

“宿舍里的小日子”可切换六种动作、四季和晴／阴／风／雨／雪／雾；点击角色挥鳍，点击电脑短暂使用笔记本，不读取真实论文。季节默认跟随北京时间月份；自动天气查询沈阳市固定坐标的 Open-Meteo current API，不使用定位或 API Key。手动选择停止查询，偏好仍通过 atmosphere 双端校验保存；天气缓存不进入旅行存档。窗景是通用校园插画，不宣称为东北大学实景。窗洞与电脑背面画稿由内置 image_gen 编辑，原 alpha 保留，提示词见 assets/layer-generation-spec-v4.json。游戏控件使用限定于 seal-travel 的楷体字体栈，不修改正文及其他界面字体。

天气模块只在游戏前台且选择自动时请求，每 15 分钟更新，10 秒超时取消，卸载与停用释放请求、计时器和监听器。当前值来源为气象模型而非气象站秒级实测；界面显示沈阳、温度、风速、北京时间数据时间和 Open-Meteo / CC BY 4.0 署名。失败保留最多 6 小时有效缓存并标明缓存，过期或无数据使用明确标注的晴天示意，可手动重试。云量控制窗外遮光与慢云，昼夜控制窗景／室内亮度，雨量控制粒子密度，风速／风向控制雨雪斜向和风线；秋季增加飘叶，无闪电频闪。现有暂停和减少动态效果契约不变。

来源与使用边界：[Open-Meteo 文档](https://open-meteo.com/en/docs)。公共免费接口限非商业使用；商业分发前需改用其商业授权或自托管服务，不能将无需密钥等同于无限制免费商用。

状态由 useTravelWorld 持有；界面只持有打开面板、选择信件和偏好草稿。场景无滚动，弹层正文独占滚动；窄屏照片和信件上下排列，关闭按钮固定。键盘沿用原生按钮与 Dialog 的 Tab/Escape/焦点归还。无新拖动手势；原工作区分屏与页签拖动继续复用。

## 持久化与资源

单独 campus-travel.json，version=2，保存伙伴名称、动画偏好、下次行囊和每次旅行的出发／来信／返程时间及已读／收藏状态。Rust 校验结构、大小、时间顺序、重复 ID 和旅程重叠，工作区锁与 revision CAS 后原子写入。写入确认后才更新界面；失败阻止继续写并要求载入核对。原 paradise.json 不读取、不改写、不删除，不迁移旧种地数据。

归来与来信按存档时间推导，关闭程序后没有后台进程或通知；再次打开结算已到期状态。仅当前可见游戏每秒更新旅行状态。Canvas 2D 场景最多 24 FPS、DPR 上限 1.5；隐藏、失焦、弹层或减少动态效果停止动画循环，缩放只调整尺寸。卸载取消帧、图片加载和超时，释放观察器、事件及画布像素缓冲；不创建 WebGL 上下文。三张素材全部就绪才显示动画，加载失败或 15 秒超时保留同一手绘拆件的静态回退及重试；存档不重置。不自动调用模型，存档上限 500 次旅程，不静默裁掉旧照片。

## 后续方向（未实现）

- 用户提供参考图后逐一制作真实地点的同风格旅行插画，保留已建立的路线／故事目录。
- 每个地点多张照片与天气／时间变化，避免重复奖励。
- 社团朋友来访、食堂菜单和校园纪念物，统一服从轻量陪伴而非签到压力。
- 后续补充二维出门／归来过场与更自然的坐姿动作；不再规划三维角色和室内几何。
- 如接入 AI 信件，默认可选、失败回退预设，不传论文正文作为旅行素材。
