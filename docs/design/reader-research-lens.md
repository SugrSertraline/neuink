# 研究问题透镜：基于 TRIZ 的阅读器创新方案

状态：产品设计，尚未实现。本文定义一个可分阶段验证的方向，不把竞品现有功能重新命名为“创新”。

## 1. 参照与当前基础

- [Zotero PDF 阅读器](https://www.zotero.org/support/pdf_reader)已支持批注进入笔记、从笔记返回 PDF 原页和引用；这应视为基础能力，而非 NeuInk 的独特卖点。
- [小绿鲸](https://www.xljsci.com/)已有全文翻译、图表解读、文献概要、思维导图、边读边问；继续叠加同类按钮无法形成清晰差异。
- [LiquidText](https://www.liquidtext.net/features)把摘录放到并行工作区并保持到原文的连接；跨页组织证据是有价值的范式。
- [Readwise Reader](https://docs.readwise.io/reader/docs/faqs/pdfs)提供 PDF / 文本视图与高亮，但两种视图的高亮并不总能互相覆盖；多表示之间的稳定映射是实际难题。

NeuInk 已有 PDF、解析片段、翻译、批注、笔记、Source Link、反向链接、助手问答、标签阅读、分屏与写入审核。尚缺一个**以研究问题为中心、把这些能力连续组织起来的阅读过程**。现有 Source Link 的 `entry_id + segment_uid + page + snapshot_text + quote_hash` 可以作为可验证的底层锚点；不能只凭页码或模型自然语言生成“引用”。

## 2. TRIZ 矛盾定义

这里将 TRIZ 用作产品设计的矛盾分析，而不机械套用面向物理工程参数的 39×39 矩阵。[TRIZ 的分离原则](https://www.ifm.eng.cam.ac.uk/uploads/Research/CTM/Roadmapping/triz_dux_trt_phase1_report.pdf)允许同一系统在不同时间、位置和条件下满足相反要求。

| 希望改善 | 随之恶化 | 使用的原理 | 转化为阅读交互 |
| --- | --- | --- | --- |
| AI 辅助更深入 | 正文被提示、标记和面板淹没 | 15 动态化、时间分离、3 局部质量 | 普通阅读完全不变；仅主动开启“问题透镜”时显示与当前问题有关的证据层 |
| 回答更快 | 用户更难核验，容易误把推断当原文 | 23 反馈、2 抽取、24 中介物 | 先取可定位片段，再生成论点；每个论点经结构化证据记录与原文双向跳转 |
| 同时看多篇论文 | 频繁切换页面、丢失阅读位置 | 1 分割、5 合并、17 另一维度 | 按“论点/证据”而非按“文件”组织临时工作集；打开证据不替换当前阅读页 |
| 自动整理省时间 | AI 悄悄改写用户的长期笔记 | 10 预先作用、23 反馈 | 临时研究卡片和正式笔记分离；预览、确认、冲突检测后才写入 |

理想最终状态：用户在阅读时提出一个研究问题，系统把“哪些内容回答它、哪些内容限制它、哪些内容与它冲突、还有哪些没有证据”放在可回到原文的位置；关闭透镜后 PDF 仍是原来的 PDF，阅读进度、选区与笔记都不受影响。

## 3. 选定创新：研究问题透镜

示例：用户打开一篇时间序列论文，输入“这个方法在不规则采样时是否仍有效？”

1. 阅读器先在当前论文的解析片段中建立候选；只有用户选择“扩大到当前标签”时，才跨论文检索。未解析 PDF 可以用原生可提取文本做页级候选，但不可伪造片段定位。
2. 助手只为真实候选返回结构化的研究卡片：`论点`、`支持证据`、`适用边界/限制`、`可能冲突`、`仍待核查`。证据引用只能指向工具给出的 `segment_uid`；宿主校验后才显示。
3. 卡片的“查看原文”在现有阅读区定位并暂时高亮相应片段；“返回问题”回到原来的阅读位置。跨论文证据在相邻页签或分屏打开，不覆盖原页。
4. 用户可标记“采纳 / 不准确 / 暂存”。纠错成为下一轮检索或模型判断的输入，不自动修改 PDF、批注或笔记。
5. “加入笔记”生成带 Source Link 的**修改提案**，在渲染后的笔记预览中审核；只有确认后才写入。事实、模型推断和用户评语在卡片和笔记中明确区分。

此处的“支持 / 冲突”是模型对给定片段的判断，不是经系统证明的事实。没有找到证据时展示“未找到足够证据”，不得显示“该结论错误”。图表只在解析结果具有可靠图像/说明锚点时纳入；纯图像不能假装已读懂其数值。

## 4. 交互与数据边界

- **入口**：PDF 和重排视图共用一个次级入口“围绕问题阅读”。也可从已选文字发起；不新增常驻侧栏或每页自动弹窗。
- **状态所有者**：一次透镜会话归当前阅读工作区的临时状态；现有 ReaderPane 持有页签/分屏，现有阅读器持有滚动位置，助手运行由现有后台任务机制持有。切换页签不丢运行，关闭会话释放临时高亮和事件监听。
- **滚动与键盘**：PDF 正文仍是唯一纵向滚动容器。证据卡片列表自有受限滚动；点击定位用既有跳转路径，返回用阅读书签。Escape 关闭临时高亮；输入框聚焦时不接管阅读快捷键。分屏拖动期间暂停高亮计算和 hover 预览。
- **数据**：检索工具返回候选；模型返回 typed `ClaimEvidenceSet`，包括 question、claim、relation、evidence_refs、uncertainty。宿主把引用解析为已有 Source Link / segment，不接受模型提供的任意文件路径、URL 或 bbox 作为本地锚点。
- **持久化**：首版问题卡片不落入正式笔记，也不自动进入资料库；只有用户审核过的提案按现有写盘规则保存。跨论文卡片可后续作为独立研究对象设计，首版不预设其 schema。
- **失效处理**：源 PDF 删除、重解析、`quote_hash` 变化时沿用来源状态检测，显式标记“来源已变化，需复核”；不静默指向同页其他文字。
- **无模型 / 解析失败**：原始阅读、手工 Source Link 与笔记仍可用；不显示空泛的 AI 卡片。可给出“先解析以获得精确证据”及重试入口。

## 5. 分阶段验证

### 第一阶段：证据路径，不引入新的写盘类型

复用现有 Source Link、来源状态与阅读跳转，在阅读器中展示“本论文已进入哪些笔记 / 哪些来源失效”。用户从笔记回原文、从原文回笔记，均保持另一侧阅读位置。此阶段不用模型，也能验证证据导航是否有价值。

验收：有来源、无来源、来源删除、来源内容变化、PDF 未解析、窄分屏；键盘可达；切换页签/分屏不重置进度；大量链接时列表不导致 PDF 重渲染。

### 第二阶段：单篇论文的问题透镜

复用助手检索和后台运行，增加结构化卡片校验与临时证据层。先只支持当前论文，不自动联网；模型不可创建不存在的证据。用户可以逐条纠错。

验收：错误/超时/取消不阻塞阅读器；证据准确跳到片段；被拒绝的模型引用不显示为有效来源；关闭透镜完全恢复普通阅读；不新增未经确认的笔记写入。

### 第三阶段：跨论文对照与提案

用户显式扩大到标签或手选论文，按论点汇总支持、限制及冲突，提供带来源的笔记提案与渲染后审核。复用现有资料检索、标签范围和修改审计，不新增 Skills 概念。

验收：同一论点的多篇证据保持各自论文身份；找不到冲突不能写成“没有冲突”；所有新增/修改笔记经过确认与冲突检测；失败不丢原始卡片。

## 6. 成功标准与明确不做

- 核验成本：从卡片到对应原文所需操作不超过一次点击；返回原阅读位置不超过一次点击。
- 来源完整性：显示为“证据”的每条引用都能定位到真实条目/片段或明确标记已失效；测试样本中不允许虚构引用。
- 阅读稳定性：开启/关闭、分屏、切换页签、后台运行、失败和取消不使 PDF 回到顶部，不增加持续渲染循环或遗留监听器。
- 用户主权：模型产物与正式笔记严格分离；所有写入均经现有预览、确认与冲突检查。

不做“AI 自动评价论文可靠性分数”、不根据关键词染色整篇 PDF、不把翻译/概要/导图改名为新功能、不把每个辅助动作做成一个新的常驻工具栏按钮。是否真的提高研究质量，需要在真实论文任务中比较用户找到反例、核验出处和完成笔记所花的时间；不能仅以模型回答速度评价。
