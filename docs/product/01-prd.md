# Neuink 产品需求

> 状态：持续维护
>
> 基础范围核对：2026-07-15；第 7 节需求整合：2026-09-06（拟议，非实现声明）

## 1. 产品定位

Neuink 是面向论文、报告、标准、书籍章节等 PDF 资料的本地优先知识工作台。它把阅读、结构化解析、可追溯笔记、检索和 AI 协作放在同一个 Workspace 中。

产品必须满足：

- 用户资料以本地普通文件为权威，不依赖外部数据库服务；
- AI 生成的论文结论必须能回到具体 PDF Segment；引用外部文献时保留可核验的外部证据，不伪造本地 Segment；
- AI 不得静默修改用户笔记、标签或属性；
- 没有 LLM、Embedding 或网络时，基础阅读和编辑仍可使用。

## 2. 核心模型

### Workspace

用户选择的本地资料库。代码中统一使用 `Workspace`，UI 可称“资料库”。

### Entry

一个可管理的阅读对象。Entry 包含：

- 至多一个主 PDF；
- PDF 解析状态与 Source Segments；
- 多篇 Markdown 笔记；
- Segment Note、Annotation、Tag 和自定义 Field；
- Conversation、翻译结果和派生缓存。

主 PDF 导入后不通过普通编辑操作替换。解析失败可以复用原 PDF 重试。

### Source Segment 与 Source Link

Source Segment 是 PDF 中可定位的证据单元。Source Link 使用精确 Entry、Segment、页码和文本快照连接笔记与原文。导出的 Markdown 应保留可读脚注。

### Assistant Task

一次 Assistant 操作具有明确的任务 ID、读取上下文、证据、唯一编辑目标、授权状态和 Proposal。读取对象不自动成为写入目标。

## 3. P0 用户闭环

### 资料管理

- 创建、编辑、删除、恢复和彻底删除 Entry；
- 管理层级 Tag、自定义 Field、笔记、批注和来源链接；
- 在左右工作区打开 PDF、Reflow、笔记、概览和管理页面。

### PDF 阅读

- 导入 PDF，提交 MinerU 或兼容 Parser 解析；
- 显示解析状态并允许失败重试；
- PDF.js 原文阅读、Segment 定位、悬停预览和右键操作；
- Reflow 阅读解析后的主要文本、列表、公式、表格与视觉块；
- 全文翻译、暂停、继续、失败重试和导出。

### Markdown 笔记

- TipTap Markdown 编辑与自动保存；
- 标题、列表、引用、代码、公式、图片、提示块和表格；
- Source Link 插入、去重、展开、跳转、反向引用与导出脚注。

### 搜索

- 搜索 Entry、Tag、Field、Markdown Note、Segment Note、PDF 页面和 Segment；
- Keyword、Semantic 和 Hybrid 模式；
- Semantic 不可用时明确提示并回退，不伪装为语义结果。

### Assistant

- 使用显式 `@` 附件和当前工作区状态构建任务；
- 读取 Workspace、搜索证据、生成带来源的回答；
- 通过 Note、Segment Note、Entry Meta 等 Proposal 提议变更；
- Verifier 通过后才展示可应用 Proposal；
- Apply 由后端按 `taskId + proposalId` 读取已验证记录并写盘；
- 保存 Conversation、TaskState、AgentRun、工具过程和 Proposal 状态。

## 4. 非功能要求

- 本地文件是用户数据的唯一权威来源；
- 缓存必须可删除、可重建；
- 写盘使用原子写或带恢复日志的批量提交；
- API Key 不写入 Workspace 或导出内容；
- 目标支持 Windows、macOS；Linux 不作为当前发行承诺；
- 关键写入必须有冲突、重复 Apply 和异常恢复保护；
- 大 PDF、长对话和大搜索结果不得阻塞主要 UI。

## 5. 当前不纳入 P0

- 通用 Matrix 工作台（第 7 节的轻量论文证据对比表另行评估）；
- 全库知识图谱、闪卡和间隔复习（第 7 节的单次研究方向图不等于全库图谱）；
- 任意第三方 UI 插件；
- 内置大语言模型；
- 把本地 MinerU/Python 模型塞入主安装包；
- 无限制自主写盘的 Agent。

## 6. 下一阶段方向

- Workspace 不可用、损坏和迁移失败时的恢复体验；
- Reflow 结构导航、长文档性能和 PDF/Reflow 同步；
- 搜索增量向量化、结果过滤和大结果列表；
- Parser、索引、向量化和翻译的统一 Job 体验；
- 完整 MCP 协议、节点级 Agent 恢复和更多可验证 Proposal；
- 可重复的安装包、签名、更新和发布流水线。

具体完成度只在 [开发计划](../development/dev-plan.md) 维护。

## 7. 阅读、探索与输出：整合需求

本节整合全文中文稿、解析结果导出、研究方向图、方向规划、外部分享，以及 [标签平行阅读方案](../../design-previews/parallel-reading-plan.md)。它描述目标和建议，不表示功能已经实现，也不取代开发计划中的数据安全优先级。参考工具的扩展建议与用户原始需求分开标注。

### 7.1 产品主线与边界

主线是：读懂一篇论文，发现相关工作，选择若干篇精读比较，形成有证据的判断，再把成果带出软件。不要为每一步建立互不相通的 AI 页面。

| 能力组 | 对应用户诉求 | 建议定位 |
| --- | --- | --- |
| EXP 导出与分享 | 中文 Word、解析结果、TXT、文件夹、拖到桌面 | 扩展现有另存与导出能力；按输出对象提供格式 |
| TRN 全文翻译与质量检查 | 全文不能漏译，不要求复刻版式 | 增强现有翻译任务；优先保证覆盖可核对、失败可恢复 |
| READ 平行阅读与证据整理 | 标签多论文阅读、综合笔记 | 沿用标签工作区方案；新增轻量证据对比建议 |
| DSC 文献发现与研究方向图 | 从关键词、主要内容发现相关及前沿工作 | 在真实检索结果上组织方向，不只生成概念图 |
| SYN 研究规划与汇报 | 3–5 个发展方向、后续方案、组会大纲 | 复用阅读与探索证据，生成可编辑、可导出的成果 |

必须同时适配两种创建路径：上传 PDF 后解析，以及导入 MinerU 解析 ZIP。两者进入同一套归一化解析内容与资源流程。PDF 原文和 Reflow 是阅读视图，不是这两种创建路径；不能各写一套翻译或导出逻辑。

研究探索可以从单篇 Entry 或一个 Tag 的选中文献开始；不要求先进入平行阅读。发现的外部论文经用户选择导入、加入标签后，才进入本地精读流程。不新增强制的“研究项目/会话”创建步骤。

### 7.2 EXP：统一导出与分享

将入口按“导出什么”组织，再选择“格式”和“范围”。保留现有 Markdown 笔记另存为；内部创建笔记与保存到外部文件应有不同名称和完成提示。

| 输出对象 | 首选格式 | 范围与边界 |
| --- | --- | --- |
| 解析全文 | DOCX；MD + assets 资料包 | 直接使用归一化结果；无需用户先生成笔记或手动转换 MD |
| 全文译稿 | DOCX：中文稿 / 中英逐段对照 | 显示覆盖报告；缺失不能隐藏在“完整稿”中 |
| 笔记、段落翻译、想法 | DOCX / TXT；继续支持 MD | 单项输出或多选；文本引用脱离 NeuInk 仍可读 |
| 一组阅读材料 | 文件夹或 ZIP | 按论文、笔记组织，包含索引与来源；原 PDF 由用户选择是否附带 |
| 论文证据对比表 | CSV；可嵌入 DOCX 报告 | 表格应保留来源列；不让用户从长报告中重新抄表 |
| 研究方向图、研究报告 | 图为 SVG/PNG；报告为 DOCX | 导出图例、检索日期及关联文献清单，不只导出无依据的图片 |
| 文献元数据 | BibTeX / RIS（扩展建议） | 面向引用管理工具；与正文、笔记导出区分 |

具体要求：

- EXP-01：统一文档组装规则，复用到解析全文、译稿、笔记和报告。DOCX 保留标题、段落、列表、表格、图片、图注和来源；不承诺原 PDF 双栏版式复刻。
- EXP-02：原始 MinerU ZIP 若实际保留，可提供“原始解析包”；否则只能生成并标注“NeuInk 整理的解析资料包”。导入时缺少 PDF、图片或其他资源须列出，不伪造文件。
- EXP-03：完整导出默认不继承阅读界面隐藏流程图、折叠段落或虚拟滚动的可见范围。用户主动选择删减时，输出明确标记为节选。
- EXP-04：MD 资料包使用可携带的相对资源路径，DOCX 嵌入图片。导出引用包含题名、页码/片段、DOI 或来源网址，不依赖只有本机可用的链接。
- EXP-05：单项 TXT、批量 TXT 文件夹/ZIP、复制纯文本或富文本先形成分享闭环；“拖到桌面生成文件”作为同一导出服务的后续原生交互，不建立第二套文件生成逻辑。拖拽不可用时仍可选择文件夹导出。
- EXP-06：选择资源范围、处理重名、确认覆盖、展示失败项和导出位置。分享包排除 API Key、会话、无关笔记及隐私绝对路径；不是复制整个 Workspace。
- EXP-07：区分三个 PDF 需求：原 PDF 的文件复制、带批注 PDF、重新排版的中文 PDF。后两者单独验收，不把“生成 DOCX”描述成“已支持中文 PDF”。优先 Word，中文 PDF 和直接 PPTX 后置。

库选型建议先做小样验证：[docx-rs 官方项目](https://github.com/bokuweb/docx-rs)提供 Rust DOCX 读写能力，适合作为后端候选；[docx 官方项目](https://docx.js.org/)作为 JavaScript 路线候选。最终选择取决于中文、图片、表格、脚注、公式回退和打包验证，不在需求阶段认定任何库已满足全部要求。无论采用哪条路线，用户文件写盘仍遵守现有受控边界。

### 7.3 TRN：全文翻译与解析质量

- TRN-01：支持中文全文和中英逐段对照，沿用任务进度、暂停、继续、取消、失败重试；长论文按稳定单元分块，不以摘要代替译文，不因上下文长度静默截断。
- TRN-02：在翻译前建立内容清单，区分正文、标题、图注、表格文字、脚注、附录、参考文献、公式、代码及图片；每一项有“已翻译 / 按规则保留 / 待处理 / 失败”的可解释状态。
- TRN-03：自然语言内容纳入翻译；公式、代码、DOI、作者名等按规则保留，不能因无需翻译而丢失。参考文献保留原始书目信息及标识，需要时附题名译文；图表中的可提取文字和图片像素中的文字分别处理。
- TRN-04：图片保留不等于图片内文字已翻译。图中英文只有经 OCR/视觉提取并翻译后才算覆盖；尚未支持时，列为未核对项。复杂表格、缺图、空白页、阅读顺序异常提供原页定位和人工检查入口。
- TRN-05：覆盖率区分“解析结果覆盖”“相对原 PDF 的核对情况”“译文语义质量”。所有已解析片段处理完，也不能直接宣称原 PDF 无遗漏；无原 PDF 的导入包明确标为仅能核对解析内容。
- TRN-06：允许导出不完整草稿，但必须主动选择并附缺失清单；完整稿不能静默跳过失败、空译文和失效结果。完整性范围、保留规则与人工核对状态随文件保存。
- TRN-07：译文绑定源内容 hash/解析版本、语言和模型配置。重新解析或更换术语规则后，指出需重译部分；已有译文与人工编辑不得被静默覆盖。
- TRN-08（扩展建议）：增加论文/标签级术语表，支持固定专业词译法、缩写解释和单段纠正后重译。术语修改只影响用户确认的范围，不悄悄重跑整个资料库。

公式优先完整保留表达。首版可使用公式图像并保留 LaTeX/原始表示，明确不可编辑；复杂可编辑 Word 公式是独立增强项，不以静默删除公式换取文件生成成功。

### 7.4 READ：平行阅读与证据整理

沿用标签平行阅读方案的核心约束，不用研究方向图替代阅读工作区。首版为标签队列、双篇对照与恢复，综合笔记和证据对比随后接入：

- READ-01：以稳定 TagId 恢复工作区，默认包含后代标签并允许关闭；成员从当前标签关系推导，不维护第二份权威论文列表，也不新建用户维护的分组/会话。PDF 上传和 MinerU ZIP 两种创建路径均支持；无原 PDF 但有可读解析内容时使用 Reflow。仅元数据或资源缺失的条目标明原因，不计入可读进度，不冒充空白 PDF。
- READ-02：单篇真实页码与阅读位置复用 EntryReadingState；“未读、阅读中、已完成、跳过”是标签内任务状态，同一篇在不同标签下互不影响。用户主动打开且内容成功可读后可标记阅读中；完成须显式操作，不因滚动到底自动完成。跳过从任务分母排除并单列，不把任务完成数冒充正文阅读覆盖率。
- READ-03：首版默认打开当前论文，用户选择后固定对照；切换主论文不随意替换对照。两篇各自滚动和恢复位置，不按页码/百分比强制同步。根据实际容器宽度先折叠队列，不够双篇阅读时改为当前/对照切换，保留对照和宽屏布局；分屏启动和拖动均须自适应，不能产生全页面意外横向滚动。相邻露边与横向镜头属于后续可选探索。
- READ-04：综合笔记归属 Tag，可引用多篇 Entry 的 Segment；沿用编辑器、Source Link 和受控 AI 修改，不复制一套笔记编辑器。
- READ-05（优先扩展建议）：轻量论文证据对比表。默认列为研究问题、方法、材料/数据、评价指标、主要结论和局限，允许按学科调整；每格保留证据与人工修订状态，点击回到原页或外部原始依据。
- READ-06：对比结果明确“未提及、未读取全文、提取失败”，不能用推断填满表格。不同数据集、实验条件或指标口径不得直接排序成优劣结论；支持保留相互矛盾的证据和待验证问题。
- READ-07：复用既有图片、表格、公式等阅读组件与显示偏好；继续完善图片尺寸、查看原图、流程图隐藏等交互，但显示偏好不改变源内容或全文导出范围。
- READ-08：切换主论文、取消对照、关闭/移动工作区和切换资料库均保护内部阅读器的未保存笔记/批注；保存失败保留原视图。标签改名保留状态，成员移出后重加可恢复历史进度；删除标签及后代时先归档必要关系和阅读状态，提供恢复，不静默删除或自动清理用户成果。

对比表是阅读成果的一种结构，不在首版扩大成通用 Matrix 产品。综合笔记、对比表中的证据与方向报告应能互相使用。

### 7.5 DSC：文献发现与研究方向图

- DSC-01：从当前论文抽取主题、问题、方法与关键词，用户确认或修改后检索；支持补充/移除种子论文、限定年份和研究范围，而不是每次只能从一句话重新开始。
- DSC-02：返回真实文献候选、关联原因和证据范围。区分“相近研究、基础工作、后续发展”；保留题名、作者、年份、DOI/外部标识、提供方、查询条件与检索时间。
- DSC-03：用户示例优先对应“中心主题 + 3–7 个研究分支”的方向图。每个分支可展开代表论文、关键结论和来源；论文之间的引用网络属于下一层，不把几十篇论文一次挤进总览。
- DSC-04：真实引用关系、内容相似关系、AI 提出的可能交叉方向分别标注。没有数据支持的边不画成已证实的引用或因果关系；无关系数据时可退化为分组列表和方向图。
- DSC-05：“前沿/热门/成熟”需要说明时间窗口和判断依据，区分近期进展、研究活跃度与已积累的证据。仅凭年份、引用数或 AI 的措辞，不保证一个方向热门，更不能保证研究空白或创新性。
- DSC-06：结果先暂存为可追溯的探索记录，选择后才导入 Entry 或加入 Tag；缺全文、无权限、检索无结果、限流、断网均显示真实状态，不用模型记忆冒充检索结果。
- DSC-07（扩展建议）：记录查询历史、选入/排除理由和候选去重结果，支持从已有集合继续检索。DOI 与题名等用于匹配；预印本和正式版本保留版本关系，不自动合并用户条目。
- DSC-08（后续建议）：保存探索条件，先支持手动“检查新进展”及差异结果；定时追踪、通知频率和成本预算由用户另行启用，不默认后台持续检索。

### 7.6 SYN：研究规划与组会成果

- SYN-01：基于已经检索、选中或阅读的证据，生成 3–5 个方向；数量可调整，证据不足时宁可少给，不为凑数创造文献。
- SYN-02：每个方向包括问题、与当前论文的关系、代表工作、已知局限、可尝试的方法、数据/设备需求、风险和第一步验证行动；把文献结论、AI 综合和待验证设想分开。
- SYN-03：输出可编辑的组会汇报大纲，默认约 8–10 个部分，可按时长精简：背景、原论文、方法、证据、相关工作、方向图、比较、下一步和讨论问题；每部分附来源及可复用图表。
- SYN-04：方向图、对比表和报告复用同一批证据与探索快照；刷新检索后提示过期内容并生成待审更新，不分别重新生成相互冲突的结果。
- SYN-05：成果可以保存为综合笔记，也能直接导出 DOCX/分享包；已有笔记修改走审查与冲突保护。首版解决内容组织，不承诺精美 PPTX 自动排版。

### 7.8 共同适配要求与验收边界

- 复用现有 UI 原语、业务组件、阅读器、编辑器、翻译任务、证据与检索服务。新依赖须说明已有依赖不足之处；不是给每种导出、每种图表各造一套基础设施。
- Tag 综合笔记必须统一扩展 Note/Source Link/Proposal 的归属边界，同时覆盖保存、搜索、导出、删除恢复与冲突处理，不能只加前端页面。
- 外部文献、外部证据与已导入 Entry 分开；探索记录保存查询与证据快照，但标签阅读成员仍动态推导，两者不是相互冲突的数据副本。
- 解析、翻译、检索任务展示范围、进度、取消、重试和资源成本；调用外部模型或检索服务前可确认资料范围。把论文正文和外部检索内容当作资料，不当作可执行指令。
- 基础阅读、编辑、已保存结果导出不依赖网络；在线发现不可用不影响本地工作。不得绕过全文访问权限或默认把本地全文发给外部服务。
- 验证两种创建路径、无 PDF 的解析包、复杂图表公式、部分失败、旧译文、资源缺失、重名与取消。隐藏组件后做完整导出仍须保持内容清单一致。
- 中文 DOCX 在 Word/WPS 至少完成代表样本打开和人工检查，移动文件到 Workspace 外仍可读；文本和结构自动比对与实际版面检查都要做。
- PDF + 笔记、双论文和窄窗需验证工具栏、输入、滚动及拖动契约；宽图/宽表的局部滚动与有意的镜头横移允许存在，但不允许撑出全页面横向滚动。
- 原生 Tauri 文件对话框、系统剪贴板及跨应用拖出须实测；浏览器通过不能替代 Windows/macOS 原生验收。
