# NeuInk 助手改进介绍：资料更精简，对话更好接续

> 这次改动整理了助手每次回答前收到的资料：固定规则统一提供，工作区发生变化时再补充，需要阅读时才取正文；对话变长后，整理讨论要点，再补发一次这轮的工作区信息。

## 可以直接讲的一分钟介绍

我们这次改进的，是助手“带着什么资料来回答问题”。

以前，每次提问前，系统会临时拼入一大包工作区信息。里面既有当前论文、笔记，也有重复的回答规则、工具说明和预先读取的正文。下一次提问时，这包信息又会重新组织，前后内容不够稳定。

现在，我们把资料分开处理：规则放在固定的位置；当前看的是哪篇论文、选中了哪份笔记，只用简短信息说明；工作区没变就不反复添加；真正需要正文时，再让助手读取。

长对话整理后，系统会先提供讨论摘要和近期原话，再补一次本轮提问时确定的论文、笔记等信息。补发后继续向后接对话，不在每一步重复添加。

用户仍然按原来的方式提问、阅读和审阅笔记。这次调整主要发生在背后的资料准备过程。

## 为什么需要改

可以把助手回答前收到的对话和资料，理解为它的“工作材料”。

假设你请一位同事帮忙读论文。第一次告诉他工作要求、论文名称和问题，是必要的。后面每追问一句，如果都重新塞给他一份夹杂规则、目录和正文的长材料，就会增加重复内容，也更难区分哪些是旧情况、哪些是新变化。

此前的准备方式有几处需要改善：

| 情况 | 需要解决的问题 |
| --- | --- |
| 连续追问同一篇论文 | 同样的工作区信息和流程说明容易反复出现 |
| 切换论文或笔记 | 需要明确告诉助手目标已经变化，或者已经清空 |
| 附加很多资料 | 尚未确定是否需要，就可能预先读取并带入正文 |
| 对话很长 | 讨论摘要和阅读状态需要更准确地接起来 |
| 使用本机助手 | 应接着它已有的会话继续，减少重复塞入历史 |

## 这次具体改了什么

### 1. 固定规则集中放好

“引用要有依据”“修改先生成提案”“失败不能说成成功”等规则，集中放在固定位置，不再跟着每轮工作区信息重复拼接。

论文推荐怎么展示、长文怎么分段读取等专项说明，跟着相应的阅读或检索能力提供。

这样，工作区信息主要回答一个问题：**这次用户关联了什么资料，当前目标是什么？**

### 2. 工作区没有变化，就不重复添加

系统会检查当前论文、笔记、选区、网页和阅读范围是否变化。

- 没变：沿用已有信息，接上新问题。
- 变了：追加一份简短的新状态，说明现在的目标。
- 取消关联：明确说明当前没有选中目标，避免继续沿用旧选择。

先前实际发送过的消息会保留下来，后续从原来的对话继续。

这里的“不重复添加”，不表示助手后面就看不到历史了。有效历史仍会随请求提供，只是不再一遍遍新增相同的工作区说明。

### 3. 先知道有什么，需要时再读正文

刚开始通常只告诉助手资料名称、当前选择和可读取的位置。论文、笔记、固定片段的正文，需要用到时再读取。

资料库目录很大时，也先提供数量和查看入口，避免一次放入上千个标题。需要找资料或遍历某个范围时，再查看完整目录。

这会减少无关资料的预先进入；第一次读取某份内容时，也可能多一个取资料的步骤。完整阅读的要求仍然需要相应的阅读工作，不能省略后直接声称读完。

### 4. 长对话整理后，补一次当前工作区

对话很长时，系统会整理较早的讨论，保留近期原话，然后在后面补一次本轮已经确定的工作区信息。

例如，助手还在处理论文 A 时，你在界面上打开了 B。中途整理长对话时，仍补充 A 的信息；等你下一次正式提问，再使用那时关联的目标。

如果是你手动整理对话，系统会在下一次提问时补充工作区；整理之后切换到 B，再发问，就使用 B。无需另外保存一份压缩起点的旧工作区。

摘要与对话一起保存在本机，原始聊天记录仍保留。系统也不再额外塞入一段“上一项任务是什么”的固定说明，让助手根据实际对话和新问题判断接下来做什么。

## 用七个例子看使用上的区别

以下是处理方式的示意，便于讲解，不代表真实模型效果的实测结果。

### 例子一：围绕同一篇论文连续追问

你打开论文 A，问：

> 这篇论文主要解决什么问题？

助手根据需要读取资料并回答。你接着问：

> 那它的实验设计有什么不足？

如果阅读目标没有变化，第二次就接着前面的实际对话继续，不再新增一整包相同的工作区说明。已有证据不够时，再读取实验部分。

**这次改善的是连续追问时的资料衔接，助手仍需为新的判断找到依据。**

### 例子二：从论文 A 切换到论文 B

刚才你在讨论论文 A，现在切换到论文 B，并关联 B 作为当前阅读目标，然后问：

> 这篇论文的方法有什么不同？

系统会补充新的目标状态，告诉助手当前关联的是 B。A 的讨论仍留在历史里，方便比较；当前指代则有了新的依据。

如果你取消所有关联，系统也会明确清空目标。此时再问“这篇论文”，目标不清楚时，助手应先澄清。

### 例子三：一百页的论文，只问其中的实验

你关联了一份很长的论文，问：

> 帮我看看实验设置是否合理。

系统不再为了准备问题，预先把大量正文塞给助手。助手可以先定位实验部分，读取相关内容，必要时再扩大阅读范围。

如果你要求“完整阅读后再总结”，仍需要继续读取相关内容。如果只取得部分文字，回答应说明阅读范围。

**按需阅读减少的是无关内容的提前进入，不会把部分阅读变成完整阅读。**

### 例子四：选了一段话，又继续阅读别处

你选中论文中的一段话并附加到对话，然后问：

> 解释一下我选中的这一段。

助手先知道你附加了一个片段，需要解释时再读取当时固定下来的内容。

即使之后原文件发生变化，这个固定片段仍对应当时选中的文字。如果你接着要求修改当前笔记，助手还必须重新读取那份笔记，不能把旧片段当成笔记的最新内容。

### 例子五：资料库里有一千篇论文

你选择“交通预测”标签，问：

> 从这个标签下的论文里，找出和缺失数据有关的研究。

系统不会先把整个资料库的一千个标题全部塞进问题。它会提供本次关联的范围，助手需要时再查看目录、检索并阅读相关论文。

如果你要求逐篇整理这个标签下的所有论文，完整范围仍然保留，需要按实际范围继续处理。

**目录可以分批查看，选中的资料范围不会因此被偷偷缩小。**

### 例子六：讨论很久之后继续写笔记

你先讨论了论文 A，后来转到论文 B，还选中了“B 的阅读笔记”。对话变长并经过整理后，你说：

> 把刚才总结的不足追加到这份笔记里。

系统会接上讨论要点、近期对话和阅读状态。助手需要确认“这份笔记”的实际目标，重新读取笔记，再生成追加内容的提案。

如果历史图表也是你要追加的内容，可以按需取回原来的图表，而不是每轮都把图表代码放进工作区。

提案仍然需要在应用里确认。生成了提案，不等于笔记已经保存。

### 例子七：换一个新需求，或使用本机助手

你上一轮正在读论文，下一轮说：

> 先放下论文，帮我想三个分享会标题。

系统不再每轮额外强调“上一项任务仍是什么”，助手应根据这句话判断你已经转向新需求。

如果使用本机安装的 Codex、Claude Code 或 OpenCode，正常续接时也会利用它已有的会话，减少反复添加同一份历史和工作区材料。请求中断时，尚未确认送达的状态会在后续请求中重新提供。

不同本机助手的支持程度有差异。OpenCode 在长对话整理后的状态衔接上，目前仍依赖它自身的摘要。

## 对使用者意味着什么

| 改进 | 预期帮助 |
| --- | --- |
| 减少重复说明 | 让更多对话空间留给问题、证据和回答 |
| 明确记录目标变化 | 减少把旧论文、旧笔记当成当前目标的机会 |
| 正文按需读取 | 减少无关材料提前进入，对大资料库更友好 |
| 历史材料保持稳定 | 为复用已经处理过的内容创造更好的条件 |
| 摘要与阅读状态一起衔接 | 让长对话继续讨论时，有更完整的恢复依据 |

这些是本次改动提供的条件，实际回答质量仍取决于模型、资料质量和阅读是否充分。

## 这次改动的范围

改动主要发生在助手背后的资料准备、对话保存、长对话整理，以及本机助手接入这些环节。

用户原有的阅读、检索和笔记审阅方式继续沿用。论文、笔记和原始聊天没有因此被删除，也没有新增一套必须学习的操作界面。写入确认、修改前读取和冲突检查继续保留。

对开发维护来说，固定规则、工作区状态、正文读取和长对话整理的职责也更清楚，后续修改某一部分时，更容易找到对应的位置。

## 目前能确认什么，还有什么要实测

已经通过自动化检查的场景，包括连续追问、切换或清空目标、保存后恢复对话、长对话整理、请求失败后的恢复，以及按需读取资料。程序的类型检查和生产构建也已通过。

对外介绍时，需要保留以下边界：

- **还没有真实费用和响应时间的前后对照。** 可以说减少了重复新增的材料、改善了内容复用条件，不能直接说已经省了多少费用或快了多少。
- **长对话整理不能保证所有细节都保留。** 重要内容仍可能需要重新查看原文。
- **没有完成真实模型效果和桌面应用人工体验的完整验收。** 自动化检查通过，不等于所有实际使用场景都已经验证。
- **本机助手仍有适配差异。** OpenCode 的长对话状态恢复还有进一步完善的空间。

## 讲解时常见的三个问题

**不重复添加工作区信息，助手会不会不知道我在看什么？**

已经提供的状态仍在有效对话里，平时发生变化时才补充新状态。长对话整理后，会在摘要和近期原话后面补一次本轮工作区，随后接着追加新消息。

**按需读取，会不会故意少读资料？**

阅读范围由问题决定。问某一段，就先读那一段；要求完整阅读，就需要继续读取。无法取得的内容，应明确说明。

**这次是不是让助手“永远不会忘记、永远不会选错目标”？**

不能这样承诺。这次改善的是给助手准备资料的方法，让已有讨论、当前目标和新变化更清楚，实际效果还需要持续验证。
