## 1. 已形成闭环

- Entry 创建、编辑、标签/属性管理、回收站、恢复和彻底删除；
- PDF 导入、Parser 提交、轮询、状态持久化和失败重试；
- PDF.js 阅读、Segment overlay/rail、Segment Note、Annotation；
- Reflow 主要 MinerU 块、列表、公式、视觉块、隐藏、翻译展示和动态高度虚拟滚动；
- Markdown 编辑、表格、公式、Source Link、反向引用和导出脚注；
- Keyword/Semantic/Hybrid 搜索、持久化向量记录、RRF 和索引状态；
- 全文翻译、暂停/继续、失败重试，以及生成内部双语 Markdown 笔记；笔记支持另存本地 MD，不等于完整译稿 DOCX 导出；
- Conversation 历史与 AgentRun；
- Router、TaskState、Evidence Ledger、Verifier、Verified Proposal；
- Note Proposal 的后端校验、幂等和 journal recovery；
- Entry Meta、Tag、Segment Note 等受控 Proposal 基础能力；
- 内置 Subagent、权限审计和进程型 MCP 工具 MVP；
- 左右 Workspace Surface、tab、分屏和 Entry Overview。

“已形成闭环”不等于已完成发行质量，回归和性能债务仍按下文处理。

### 5.4 首批导出实现与验证

- PDF 和 Reflow 共用 `PaperExportDialog`。支持解析全文、中文译稿、中英对照，输出 DOCX、TXT 或包含 `paper.md`、图片与 `coverage.json` 的 ZIP；此 ZIP 明确标为 NeuInk 整理包，不冒充原始 MinerU ZIP。
- 新增 `shared/ipc/exportApi.ts` → `inspect_paper_export` / `export_paper` → `neuink-workspace::export` 调用链。读取与生成在 blocking worker 运行，不在 React 或 Tauri 主线程处理图像与压缩。
- 逐项核对非空译文、源文本及兼容现有翻译记录的源 hash；未译、失败、旧译文在草稿保留原文，不直接丢弃。图片内文字未核验或资源缺失时也须显式同意草稿；所有文件说明未逐页核对原 PDF。
- 导出范围读取完整归一化结果，不接收隐藏/折叠/虚拟列表参数。测试覆盖有无原 PDF、MinerU ZIP 写入后内容一致，以及 Markdown/HTML 图片引用重写不误改正文和代码。

### 5.5 Mermaid 与导出版式适配

- 已核对真实资料库：流程图通常是 Figure，`text` 含 Mermaid 围栏，`markdown` 为空，`asset_path` 指向原图；标题级别保存在 `mineru_metadata.level`，图注通过 `block_role=caption` 标识。不能仅依赖 Markdown 标题或把图片当普通源码。
- 共用导出弹窗新增四种方式：原图（默认）、Mermaid 渲染 PNG、可复制源码、原图加文末源码附录。普通图片不受流程图选项影响；源码相关 ZIP 附 `.mmd`。原图缺失保留源码并提示草稿，渲染失败不落盘，不擅自补画或修改源码。
- Word 统一标题层级、图注、正文强调、代码字体、图片居中及等比边界；图片最大宽度提供 60% / 85% / 100%，小图不强制放大。逐段来源编号默认关闭，核对时可以打开。保留解析内容的前提下做单栏排版，不承诺复刻 PDF。
- 继续使用现有 Dialog/Select/Switch、Mermaid、`docx-rs` 和图片库，无新增依赖。设置与任务状态归导出弹窗；正文设置/报告共用一个纵向滚动区，头尾固定，保存中阻止关闭及重复提交；无新增拖动行为。导出准备与 Word 文本样式拆成独立模块，避免持续膨胀单一导出文件。
- 自动验证：前端 120 文件 / 416 测试；Workspace 57 测试（20 项导出回归），另有 2 项手动 QA 测试默认跳过。真实论文的四种模式分别生成 DOCX/ZIP，手动 QA 测试通过；确认 29 个正文标题、10 个图注及图片/表格结构，源码模式替换流程图原图而不移除其他图片。
- 使用 Edge 无头浏览器调用实际导出渲染模块检查 3 份真实 Mermaid：2 份成功转换并检查 PNG，1 份因语法异常阻止导出。此结果不证明 Mermaid 识别语义正确。TypeScript、前端生产构建与工作区编译检查通过；既有大 chunk / PDF.js 混合导入提示仍存在。
- 文档技能渲染器再次因缺少 bundled `soffice.exe` 失败，未完成 Word/WPS 全文分页版面验收；未完成原生 Tauri 文件对话框、WebView2 渲染和 125% 视觉验收。桌面开发版已自动重编译运行，可继续人工测试。

### 5.8 重要缺陷检查与编辑安全修复（2026-09-06）

- 范围：优先检查编辑—保存—关闭/跨分屏—Workspace 切换—后台回收，以及片段记录读取/定位；不新增 Tab 类型或注册框架，不代表全库所有业务均已完成审计。
- 修复真实编辑器传入旧 `entry-content:<id>|...`、关闭/导出使用 canonical surface key 导致的漏检；传递独立 editorScopeKey，注册表统一兼容旧标识。关闭当前页、其他页和整个分屏复用一套确认，冻结关闭目标集合，任一保存失败或保存期间又有编辑则全部保留。取消/键盘 Escape 保留草稿并恢复入口焦点。
- 切换资料库同时检查并保存文档笔记、片段笔记和批注；失败取消切换。跨分屏移动/交换有未保存内容时拦截，同分屏排序不受影响。有草稿或正在保存的隐藏阅读器不回收，干净后重新累计五分钟空闲时间；Workspace root 变化后重建 ReaderPane，清除旧库临时 UI 状态。
- 片段保存确认提交的快照，保留保存期间本页或另一分屏的新输入；即使文本暂时改回旧基线，待完成保存仍受保护。批注不再把旧列表刷新误认为保存成功，仅实际成功后清草稿；失败继续编辑。切换片段记录类型也检查未保存内容。
- 重复打开已有片段记录更新 active 与 tab 列表中的定位/模式；读取失败有错误和重试，刷新失败保留已加载数据及编辑器，迟到响应不跨条目/资料库生效。跨页笔记按真实 UID 存储、按逻辑 UID 打开时不再丢失显示；PDF、Reflow 和记录页共用 `buildSegmentNoteLookup`，移除重复查找实现。
- 复用已有保存回调/注册表和 Dialog/Button/语义 token，无新增依赖和数据格式。关闭确认状态归共享 hook，加载和后台回收分别拆为独立 hook；保留现有大阅读页作为编排层，避免同时做无关重写。正文仍使用原有滚动区域，错误条固定在正文上方，无新增拖动处理。
- 加入刷新和原生窗口关闭保护，有未保存修改时提示回页内保存/明确放弃。已核对安装版本的 Tauri API：允许关闭后由监听器调用 destroy，因此主窗口补充对应 capability。监听器与异步清理有模拟测试；突然崩溃/强制结束进程/断电的恢复不在此次保证内。
- 验证：全量前端 129 文件 / 468 测试；`cargo test --workspace` 通过（Workspace 69 通过、3 项手动 QA 默认跳过），TypeScript 与生产构建通过，既有 PDF.js 混合导入和大 chunk 警告仍存在。Edge 无头浏览器验证真实批注编辑器 → 旧标识注册 → canonical 关闭保护的完整链路，1200/640/420 px、100%/125% 下无弹窗横向溢出，取消/焦点恢复、保存失败保留、明确放弃及错误条重试通过，已查看最窄截图。

### 5.10 标签平行阅读 B1 实施（2026-09-06）

- `src-tauri/tauri.conf.json` 只声明 main，`capabilities/default.json` 也只授权 main；`src-tauri/src/lib.rs` 尚无业务窗口注册、交接与退出协调。
- `WorkspaceTabsBar.tsx` 的拖动依赖当前 document 命中检测，并在窗口失焦时取消，只支持窗内重排／分屏，不具备原生跨窗口拖动能力。
- `assistantBackgroundRuns.ts` 的 Map／AbortController／回调属于窗口 JS 运行时。现有“后台运行”覆盖面板切换／卸载，不覆盖窗口销毁。复制 App 会启动独立注册表，不能据此保证同一会话单执行者。
- `noteEditLease.ts`、dirty registries 和关闭保护属于当前窗口；已有 Rust Note revision 与 Task checkpoint CAS 是安全基础，但不能代替跨窗口编辑权交接。Conversation 的消息与索引写入也要统一协调，不能让多个视图各自保存整段会话。
- `useWorkspace.ts` 的资料库和选择状态是 hook 本地状态；目前有 Job／翻译进度广播，但没有覆盖所有 Entry／Note／Tag／Conversation 修改的统一失效通知。直接开多窗会出现旧数据和最后写入覆盖布局偏好的问题。

### 7.2 状态所有权与产品契约

| 状态 | 拟议所有者 | 窗口行为 |
| --- | --- | --- |
| Agent 执行、工具调用、队列、停止信号 | 独立且唯一的 TS 执行宿主 | 视图只发送命令、订阅流；拆窗不重新发问、不复制工具执行 |
| 窗口注册、交接、编辑租约、写盘协调 | Rust 应用级服务 | 按 workspace + resource ID 校验；窗口不可绕过 |
| Entry／Note／Source Link／Conversation 正文 | 既有 Rust 持久化层 | 版本检查、原子保存、事件失效后重读 |
| 页签、焦点、侧栏选择、滚动、缩放 | 各可见窗口的视图状态 | 分窗独立；交接时显式迁移，不反向覆盖其它窗口 |
| 笔记／输入框草稿及选择区 | 活跃编辑视图，交接时由协调器暂存 | 未确认接收前不销毁原视图；同资源默认仅一个可写编辑者 |

- 推荐先用应用专有的隐藏 WebView 承载现有 TS Agent，Rust 管理其生命周期与访问边界；这是拟议方案，须先做启动、保活、权限、HTTP 与异常恢复验证。无需为了多窗口把 Agent 推理循环重写成 Rust，也不引入 Node sidecar 作为默认前提。
- 独立窗口从与 main 相同的受信任本地入口创建，使用受校验的 surface 描述和一次性交接 token，不接受任意 URL 或借窗口传 API Key。权限按窗口角色最小化配置，不直接把所有窗口 wildcard 授予全部能力。
- 第一版默认是“移动该页面”，不是复制可编辑文档。同一会话可多处观察，但发送／排队／停止由执行宿主串行协调；同一笔记第二个视图只读或请求接管。设置等共享编辑也要有版本／所有者控制。
- 关闭聊天视图不等于停止任务；关闭主窗口不应销毁执行宿主。最后一个可见窗口关闭时，有运行任务则提供明确后台保留／退出选择和重新打开入口；明确退出应用时统一处理未保存内容与运行任务。进程崩溃仅按 checkpoint 恢复，禁止静默重放已成功的写入工具。
- 初版所有窗口绑定同一 Workspace，切换资料库需全局协调未保存内容与后台任务；不允许单个窗口改全局 root 而其它窗口仍按旧上下文写入。
- 来源跳转保留 Source Link 的 workspace／Entry／Segment／页码和快照：优先定位已有对应阅读窗口，否则在发起窗口的阅读区域打开；不得强制把主窗口左侧从搜索／对话切换成详情。

### 7.3 实施切片与验收门槛

1. **共享状态基础**：抽离 App 窗口壳与 Surface 渲染；建立 Rust 窗口／资源注册、版本事件、窗口级偏好命名空间和编辑租约。事件携带版本，窗口恢复订阅后按版本重读，不能假定事件永不丢失。
2. **Agent 独立宿主**：把窗口 Map 的运行控制迁到唯一 TS 宿主，UI 通过 typed IPC／事件读取 snapshot + 增量。按 task／conversation 去重，重连不重复模型调用；任务触发的 UI 操作通过命令路由给可见窗口，业务写入仍复用受控工具和 Verified Proposal。
3. **菜单式拆出与移回**：复用 ContextMenu／Button／TitleBar；tab 右键“移到新窗口”，助手标题提供同等入口，独立窗口支持“移回主窗口”。交接顺序为冻结并保存或暂存草稿 → 创建目标 → ready + 状态恢复确认 → 转移租约 → 移除原 tab；超时／失败保留原窗口与草稿。目标未确认前不得把原页面当作用户关闭处理。
4. **浏览器式拖出／拖回**：复用同一交接协议，另做原生坐标／跨窗口命中与窗口管理桥接；验证多显示器、负坐标、不同 DPI／缩放、失焦、Escape／取消、拖出边界、目标窗口关闭等，不把当前 document pointer handler 直接当跨窗实现。提供菜单与键盘等价操作，拖动时暂停 hover preview。
5. **恢复与回归**：逐类验收 PDF、重排、Entry／Tag 笔记、片段笔记／批注、条目库／标签／关系、设置、助手和其它 WorkspaceSurface；保留原组件的正常、加载、空、错误、只读、键盘、滚动与拖动状态。阅读滚动仍归 Reader，笔记归编辑器，聊天归消息视口；窗口壳不增加第二层正文滚动。

发布前必须在原生 Tauri 实测：流式回复期间反复拆回只执行一次；关闭主窗口后任务仍可观测；两个窗口编辑同一笔记不会丢失／覆盖；Source Link 原文及快照跨窗可用；创建失败、关闭取消、崩溃重开、全局退出和切换 Workspace 均有确定行为。浏览器预览或单窗口测试不能替代这些验收。
