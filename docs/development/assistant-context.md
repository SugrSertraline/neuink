# 助手上下文工程

当前实现采用“小型初始上下文 + 追加式状态变化 + 工具读取正文”。上下文工程集中在 `apps/desktop/src/modules/assistant/context/`；UI、执行权限和文档存储继续由原模块负责。

## 模型请求结构

1. 固定系统规则、稳定 Agent 配置和按名称排序的工具声明。
2. 有 compact 时，先放入讨论摘要。
3. 原样保留的近期模型消息，包括此前真正发送的工作区状态、用户问题和完整工具结果。
4. 自动 compact 在近期原文之后补发一次本轮冻结的工作区和执行策略，后续过程消息继续追加在它们之后。
5. 新用户轮次有状态变化时再追加新状态，然后追加用户原文。

工作区变化使用小型完整快照：切换目标、清空目标、引用变化、内容版本或浏览器导航变化都会生成新快照。未变化时只追加用户问题；不删除、替换或重新生成先前消息。状态判断采用确定性 JSON，忽略 UI 时间戳等非语义字段。不存在 `Previous task state` 拼接，任务是否延续由模型根据对话判断。

引用格式、提案确认、失败语义和非可信资料规则只在固定系统策略中维护。分页、推荐列表等专项合同放在对应工具声明或实际返回结果中。仅真实出现的能力缺失、读取失败和执行限额作为后续观察追加。

## 工作区信息与正文

- 常驻状态仅含范围、当前论文/笔记的 ID、标题与版本，浏览器的安全标识及引用映射。
- 选区正文保存在宿主原有上下文快照中。模型先收到带内容 hash 的 `context_ref`，实际调用读取工具后才取得正文和引用编号。
- 目录超过 20 条或序列化后超过 6,000 字符时，仅传数量和 `scope:` 引用；完整目录按需分页读取。大型标签范围使用同一机制，宿主检索范围保持完整。
- 元数据初始化不解析笔记正文、PDF 或片段文件。论文/笔记版本用于检测变化；修改时仍必须重新读取内容并走原有 hash、冲突检测和提案流程。
- 历史图表按需取回原始代码及有限的已存证据快照；历史检索返回原始分页参数。缺失或版本不符时明确失败，不默默换成新内容。

## compact 总结的位置

持久化总结位于 Conversation 消息的 `parts[type="memory"].memory`，沿用原有 Conversation 存储；没有另外生成总结文件。`summary` 是讨论摘要正文。自动压缩另存 `retained_context`，按实际顺序保存近期原文、补发的工作区/执行策略和后续过程消息；不再写入 `context_baseline`。运行中的派生投影还会保存到执行检查点。

自动压缩成功后，从本轮已有的真实宿主消息中取出最后有效的工作区和执行策略，原样补到近期原文之后，不读取压缩时的实时界面，也不让摘要模型推断状态。投影只记录补发时的原始消息位置 `contextRefreshIndex`，不再单独保存边界处工作区；后续工具步骤在固定位置之后增长，避免反复把工作区搬到末尾。缺失某类宿主状态时不编造；明确清空的状态仍会补发。

手动压缩只保存讨论摘要和原有统计信息，下一次提问按该次冻结的工作区和执行策略补发；若用户在手动压缩后切换目标，使用新问题的目标。摘要的 UI 计数和更新时间不进入模型前缀。原始会话和工具记录仍保留；摘要失败、取消或补发后仍超容量时，不推进压缩检查点。

## 持久化兼容与本地 Agent

`model-transcript` v2 保存 `inputMessages`（该用户轮新增的真实输入）和后续输出；历史调用 ID 保持原样。同模型保留兼容的协议元数据，切换模型时移除不兼容部分。v1 与旧纯文本会话仍可读取；其缺失的原始输入无法追溯恢复，首次迁移不承诺沿用旧缓存。保留窗口兼容 v1/v2。投影 v5 恢复自身时保留补发位置；读取旧 v3/v4 时保留摘要与历史边界，忽略旧 `baseline`，以当前冻结消息补发一次并清除旧请求的用量锚点。旧会话里的 `context_baseline` 留在磁盘但不再参与请求组装，不批量迁移或重写历史文件。

Codex、Claude Code、OpenCode 管理自己的原生历史。新会话只引导一次历史摘要/近期可见对话；正常续接只发送变化。`contextState` 在本次原生请求成功返回后确认并持久化，初始化通知不表示新上下文已送达。收到 Claude compact boundary 或 Codex compact 通知时清除已确认状态，下轮重新发送。OpenCode 当前未接入可靠的 compact 通知，仍依赖其原生总结保留状态；需要重新提供状态时可新建会话。

Claude/Codex 通过各自系统/开发者指令通道接收公共规则。OpenCode ACP 当前使用首次会话消息引导；正常续接不重复规则，旧会话或已失效状态可重新引导。原生权限、人工确认和实际工具执行检查继续由宿主控制。

## 验证与限制

确定性测试覆盖真实 Provider 驱动下的连续请求前缀、状态不变/改变/清空、补发位置固定、持久化重放、compact 边界、旧投影兼容、失败恢复、只读权限、目录引用及 Unicode 分页。后端测试用损坏的正文文件验证初始化只读取元数据。

固定规则、模型或授权工具配置改变，以及 compact 主动替换历史时，都会建立新前缀。模型服务是否命中缓存还受供应商、路由、缓存时效与最小长度约束；本次改动消除宿主改写历史造成的失效，不保证服务端命中率。本次未进行真实供应商缓存用量对照或原生 Tauri 视觉验收。
