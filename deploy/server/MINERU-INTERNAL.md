# 内部部署：NeuInk 账号解析与 MinerU

本说明和 Compose 文件是部署模板，不包含服务器地址、数据库密码或证书。上线须使用已构建并验证的 NeuInk 镜像；仅添加配置不会让旧版服务支持解析队列。当前机器的 MinerU 容器使用独立镜像，升级 NeuInk 时应保持其输入、输出与模型目录。

## 网络与配置

`compose.lan.yaml` 保留 HTTPS；`compose.lan-http.yaml` 是可选的局域网 HTTP 基础配置。HTTP 会明文传送密码、会话和论文，只用于明确允许的隔离测试网络，并绑定指定内网接口与防火墙来源；客户端支持及提示需在切换前实测。HTTP 模板不挂载证书，应用 `/data`、数据库目录和原配置一致，且仍需原有磁盘挂载检查。

使用 `compose.mineru.yaml` 作为额外覆盖文件，将 app 连接到独立的内部 Docker 网络。`NEUINK_MINERU_NETWORK` 设置为运维者选定的专用网络名，`mineru` 是该网络上的容器别名，不是对外地址。部署者应确认网络名称未被其他服务使用，并检查网络成员；将已有 MinerU 容器加入该网络时指定别名 `mineru`。网络应以 `--internal` 创建，不发布 MinerU 的端口；保留原容器的本机绑定仅供维护，核对主机防火墙、其他反向代理和 IPv6 是否另有暴露。容器重建后必须重新连接专用网络并确认别名，不能依赖容器 IP。

示例配置使用 `NEUINK_PARSE_ENABLED=true` 和 `NEUINK_PARSE_UPSTREAM=http://mineru:8000`；最大论文默认 256 MiB，轮询间隔默认 3000 毫秒，按服务器容量调整。实际并发与队列限制以应用版本为准，当前硬件初始并发建议为 1。上传使用现有分片机制；8 MiB 是单请求保护，不应为整个论文关闭。仅使用 NeuInk 认证入口并不自动关闭其他机器上可能存在的 MinerU 代理，需要单独核查。

## 上线和回滚

1. 记录候选源码版本、镜像摘要、当前 Compose 文件与旧镜像摘要，配置文件和备份仅存受限位置，不将实际地址或凭据提交仓库。核查数据库及文件所在磁盘已挂载，留足空间。
2. 用独立数据库、附件目录、测试账号、端口和 MinerU 测试实例验证候选：未经登录拒绝解析；用户不能读取他人任务或附件；20 MiB 以上文件可分片上传；并发排队、取消、重试、异常断线、服务和 MinerU 重启、结果下载和资源清理均有明确结果。已有同步、登录、附件和资料库必须回归。不要将未完成的其他 alpha 改动一起部署。
3. 停止其他管理写入。使用现有 `backup.py backup` 执行一致性备份并 `verify`；该脚本会短暂停止 app，复制数据库、附件及配置中的 TLS 文件。备份目标必须是新建、非活动数据目录，严格遵守脚本的挂载检查。随后在独立的空项目及空目录中试恢复、验证登录和文件读取；保留旧镜像。先确认测试可靠，再进行切换。
4. 根据实际部署文件追加解析覆盖配置，避免覆盖已有 `/ops`、证书、数据挂载及安全选项。先离线检查合并后的 Compose 配置，不在日志输出展开的凭据。更新前检查无正在运行的解析任务；仅替换 app 并验证 `/health`、`/ready`、登录、同步和解析。失败时保留日志，不反复重启或清理数据。
5. 回滚前先隔离写入并备份切换后的数据。确认数据库迁移与旧镜像兼容后才能切回旧镜像；若不兼容，使用经过验证的备份恢复到新的空目录和隔离项目，再决定切换。恢复旧备份会产生新的服务器 epoch 并撤销旧会话，且会丢失备份之后的新写入；不可直接覆盖现有数据库或静默执行降级。确认业务后再重新启用入口。

本模板尚未对当前实际服务执行切换，也不证明 HTTP、解析队列或多用户隔离已通过端到端验收。
