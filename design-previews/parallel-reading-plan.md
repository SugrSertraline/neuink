# NeuInk 标签平行阅读功能方案

> 2026-09-06 调研后收敛的实施方案；功能实现与验收状态以 [开发计划第 5 节](../docs/development/dev-plan.md#5-阅读成果与研究探索拟议路线) 为准。
>
> [镜头式平行阅读 HTML 预览](./parallel-reading.html) 保留为后续探索，不是首版验收目标。

> 实施更新：B1 已接通标签入口、动态队列、双篇独立阅读、状态保存和标签恢复，自动测试及模拟 IPC 的实际阅读器浏览器回归已通过；原生 Tauri 验收待补。当前实现见 [系统架构](../docs/architecture/system-architecture.md#标签平行阅读b1)。本文后续章节仍包含 B2/B3 目标，不能作为全部已实现能力。
>
> B2 本地编辑更新：已增加打开原有文档笔记、真实 Tag-owned 综合笔记、两栏切换、跨篇来源、Word/TXT 输出和软删除恢复。全局搜索、反向来源列表及 Assistant/Proposal 适配仍未完成，不能把整个 B2 标记为完成；实现与验收详见开发计划 5.15。

## 1. 结论

平行阅读不设计成由用户手工创建、命名和维护的独立“阅读会话”，而采用以下产品定义：

> **每个标签天然拥有一个可恢复的平行阅读工作区。**

用户只需要进入标签并点击“进入平行阅读”。系统根据该标签及其子标签实时确定论文集合，并保存阅读顺序、每篇论文在该标签下的阅读状态、当前论文和对照论文。

首版 B1 完成“标签队列 → 双篇对照 → 标记与继续 → 退出后恢复”这一闭环。B2 再接标签综合笔记和跨篇来源，B3 接轻量证据对比；不让横向镜头、通用 Tab 框架或研究图成为首版前置条件。

该方案把三类关系分开：

1. `Entry → PDF`：一篇可管理论文至多绑定一个主 PDF；
2. `Tag → Entry[]`：标签决定参与平行阅读的论文集合；
3. `TagReadingWorkspace → ReadingState`：标签工作区保存阅读任务与布局状态，不复制论文和单篇阅读位置。

因此，不需要把多个 PDF 塞进同一个 Entry，也不需要复制一套用户管理的 Collection/Session 概念。一个条目可属于多个标签；标签层级只是组织关系，不等于复制本地文件。PDF 上传与 MinerU ZIP 导入都是合法来源，不能把“存在主 PDF”作为整个平行阅读功能的门槛。

## 2. 目标与非目标

### 2.1 目标

- 用户可以直接针对一个标签进入或继续平行阅读；
- 同时阅读、对照和引用多篇论文；
- 离开后能够恢复当前论文、对照论文、阅读位置与标签内进度；
- 标签成员变化时，阅读集合自动更新；
- 同一篇论文可以在不同标签工作区中拥有不同的任务状态；
- 保留 NeuInk 的本地优先、可追溯来源和离线阅读能力。

### 2.2 非目标

- 不允许一个 Entry 直接绑定多个主 PDF；
- 不在第一阶段实现复杂的论文关系图谱；
- 不同时完整渲染大量 PDF 页面；
- 不用平行阅读替代现有的普通单篇阅读和左右分屏；
- 不让 AI 自动改变标签、完成状态或综合笔记。
- 首版不增加综合笔记所有权、证据矩阵、横向镜头、多个阅读轮次或同步滚动。

## 3. 实施前能力与缺口（调研基线）

### 3.1 当前已经具备

- `EntryMeta` 支持多个标签、至多一个 PDF 和多篇 Entry 笔记；
- PDF 导入会拒绝给已有 PDF 的 Entry 再绑定第二个 PDF；
- `WorkspaceSurfaceLayout` 已支持左右 pane、tab、焦点和分屏；
- 标签页面可以包含当前标签及其后代标签下的全部 Entry；
- Assistant 的标签范围可以扩展到多个 Entry；
- `SourceLink.sources` 可以引用不同 Entry 的 Segment；
- 已有 `EntryReadingState`，可以持久化单篇论文的模式、当前页、访问页、阅读时长和最近阅读时间。

### 3.2 实施前缺少

- 没有以 Tag 为键的可恢复阅读工作区；
- 没有标签语境下的未读、阅读中、已完成和跳过状态；
- 没有标签工作区的固定对照论文、队列顺序与布局恢复；
- 没有真正归属于标签工作区的综合笔记；
- 没有从标签直接进入平行阅读的产品入口；
- 现有左右分屏只能临时并排两个页面，不能表达一个持续的多论文阅读任务。
- 当前 `Workspace::delete_tag` 直接删除标签及后代关系并逐项更新 Entry，没有标签阅读数据的归档/恢复事务；不能假定现有 Entry 回收站已覆盖 Tag。

## 4. 核心概念

### 4.1 标签阅读工作区

`TagReadingWorkspace` 与 `TagId` 一一对应，首次进入时惰性初始化，之后继续进入时恢复。

- 用户不需要填写名称；工作区名称直接使用标签路径；
- 标签重命名不会破坏工作区，因为关联使用 `TagId`；
- 默认包含当前标签和全部后代标签；
- 论文成员实时从标签关系推导，不保存一份重复的权威成员列表。

### 4.2 论文成员

成员集合按以下规则计算：

```text
候选成员 = 具有当前 Tag 或其后代 Tag，且未进入回收站的全部 Entry
可读队列 = 候选成员中，存在可用原 PDF 或可阅读归一化解析内容的 Entry
```

- 同一 Entry 命中多个后代标签时只出现一次；
- 有原 PDF：可使用 PDF 视图；有可读解析结果：可使用 Reflow；两者都有时尊重现有阅读模式偏好；
- 无 PDF 的 MinerU ZIP 条目正常进入队列，默认 Reflow；只有元数据/笔记或资源暂缺的条目单列“暂不可读”，不冒充空白 PDF，也不计入可读进度分母；
- 可用性由 Workspace 校验实际资源和可读内容，不能只依赖 `pdfFileName`、创建方式或解析任务状态；
- 解析失败不影响可用的原始 PDF 阅读；尚无可用解析内容时禁用 Reflow 和 Segment 能力。重试失败但仍有可用旧解析时显示版本/失败提示，不单凭任务状态禁用旧内容；
- 新增到标签的论文自动进入队列，初始为“未读”；
- 从标签移除的论文退出进度统计，但保留历史任务状态，重新加入时可以恢复。

### 4.3 单篇阅读状态与标签任务状态

两类状态不能混为一体：

| 状态 | 所属范围 | 示例 |
| --- | --- | --- |
| `EntryReadingState` | 全局单篇论文 | 当前页、访问页、PDF/Reflow 模式、阅读时长 |
| `TagMemberReadingState` | 某个标签工作区 | 未读、阅读中、已完成、跳过、队列顺序 |

同一篇论文在不同标签下可以分别为“已完成”和“未读”，但打开时复用现有单篇阅读位置。论文自身的笔记、批注、译文也继续归 Entry 所有，不为每个标签复制一份。

两篇不同论文各自滚动，不按页码或百分比强行同步。同一 Entry 在其他页面更新阅读位置，不应令当前正在读的页面突然跳转；恢复时读取位置、阅读中本地控制，持久化仍使用现有所有者。只累计当前实际活跃阅读的时长，不能因两篇同时挂载而重复计时。

## 5. 用户流程

### 5.1 入口

标签被选中后，在标签页面标题区提供主操作：

- 从未进入：`进入平行阅读`；
- 已有状态：`继续平行阅读 · 3/8`；
- 首版只在工作区及标签页面提供进度，标签树汇总后置，避免为每个树节点读取所有文档。

首次进入不弹出创建 Dialog，直接完成：

1. 解析标签成员；
2. 选择第一篇“阅读中”或“未读”论文；
3. 打开当前论文；用户选择“设为对照”后再打开第二篇，不预选无关论文，不生成空综合笔记；
4. 保存初始阅读状态。只有一篇可读论文也可进入，空标签显示可添加条目的空状态。

### 5.2 阅读

左侧标签论文队列显示：

- 阅读顺序；
- 未读、阅读中、已完成、跳过状态；
- 实际阅读模式和可取得的单篇进度；无有效页数时不伪造百分比；
- 仅解析结果、解析中、原文可读但重排不可用、资源缺失等状态。

点击队列中的论文，将其送入当前论文视图；“设为对照”是独立操作。对照论文在切换主论文时保持不变。主文候选与对照相同时交换两侧，避免同一论文重复占据两个槽位；“标记已读并继续”优先选非对照的未读论文，无其他未读时停留并提示，可由用户主动交换。

首版按稳定队列顺序展示，可用明确的“上移/下移”操作排序；不新建拖动引擎。搜索/筛选只影响队列展示，不偷偷改变整个标签的成员和进度。

### 5.3 完成与继续

- 用户主动打开未读论文且阅读器成功可读后，标签任务状态改为“阅读中”；预加载、错误、列表展示和后台恢复不自动改状态；
- “标记已读并继续”是显式动作，不根据滚动到底自动完成；
- 完成后按队列顺序向后寻找非对照的未读论文，末尾允许回绕一次；没有候选则停留并提示，不自动替换固定对照；
- “跳过”表示本轮不阅读，从完成分母中排除，并单独显示跳过数量；
- 用户可以在当前标签内将已完成论文重新设为“阅读中”。
- 当前可读成员中的完成数 /（当前可读数 − 其中跳过数）表示本标签任务进度；暂不可读和跳过数量另列。分母为零时显示“暂无待读论文”，不显示误导性的 100%。
- 不提供“重置所有进度”作为首版快捷动作；重新阅读单篇由用户明确修改状态。

### 5.4 退出与恢复

退出时保存：

- 当前论文与对照论文；
- 左侧队列折叠偏好与双篇比例；
- 标签任务状态和排序。

单篇阅读模式、页码、访问页和阅读时长继续由现有 `EntryReadingState` 保存，不在标签状态中重复写入。窄屏降级只影响显示，不清除对照论文及宽屏布局偏好。

## 6. 界面方案

### 6.1 页面结构

```text
┌──────────────────────────────────────────────────────────────┐
│ 标签路径 / 标签名称 / 阅读进度 / 继续状态                    │
├──────────────┬───────────────────────────────────────────────┤
│ 标签论文队列 │ 当前论文 / 对照论文 / 标记已读并继续          │
│              ├───────────────────────────────────────────────┤
│ 3/8          │  当前论文 A       │ 固定对照论文 B（可选）    │
│ 未读/进行中  │  PDF / Reflow     │ PDF / Reflow              │
│ 已完成/跳过  │  独立滚动         │ 独立滚动                  │
└──────────────┴───────────────────────────────────────────────┘
```

### 6.2 响应式双篇视图

- 宽度以实际阅读容器为准，不以窗口宽度猜测；已有侧栏、外层分屏和系统缩放都会占用空间；
- 空间足够时两篇并排，初始各占一半；只打开一篇时占满正文区；
- 拖动分界线时 PDF 自动适宽策略及 Reflow 均响应容器变化，显式手动缩放继续尊重用户选择；
- 先折叠队列；若两篇仍无法各自提供可操作的阅读宽度，则只显示一个槽位，顶部用“当前 / 对照”切换。不是把两篇硬塞进极窄双栏，也不是纵向叠成两个竞争滚动的大页面；
- 窄屏显示切换不改变当前/对照角色、完成状态或阅读位置；宽度恢复后恢复原双栏比例；
- 队列折叠是布局动作，不移除论文；无对照时不留空白占位列；
- 首版没有横向镜头轨道、露边、镜头动画或 `Shift + 滚轮` 劫持。复杂图/表或手动放大的 PDF 可以局部横滚，但不能撑出整个工作区的横向滚动条；
- 双栏最低可读宽度应通过实际工具栏、100%/125% 缩放和最窄支持容器测试确定，不能把原型的固定露边尺寸当成断点。

### 6.3 视图类型

首版支持：

- Entry PDF；
- Entry Reflow；

后续可增加：

- 对照矩阵；
- 标签综合笔记；
- Assistant 回答；
- 单篇论文概览。

### 6.4 关闭、切换与编辑保护

首版只区分“折叠队列”“窄屏切换显示”“取消对照”和“关闭工作区”，不引入任意视图的隐藏/打开列表。

取消对照只解除这个槽位，不删除论文、标签关系、笔记或阅读进度。切换主论文、交换两侧、关闭/移动整个工作区、切换资料库时，必须检查受影响阅读器的片段笔记与批注草稿。用户取消则保持原论文和焦点；保存失败或保存中出现新编辑则保留草稿和视图，不先卸载再提示。

新工作区的嵌套阅读器必须有可追溯到父 Surface 的草稿作用域；不能内部注册 `pdf:<entryId>`，关闭时却只查 `tag-reading:<tagId>`。后续综合笔记也使用同一保护链。

### 6.5 滚动所有权

每个方向只保留一个明确的主要滚动所有者：

| 区域 | 滚动方向 | 所有者 |
| --- | --- | --- |
| 标签论文队列 | 纵向 | 队列容器 |
| PDF/Reflow | 纵向 | 各自阅读器 |
| 超宽图表/手动缩放 PDF | 横向 | 相应内容容器，不是工作区根节点 |
| 后续综合笔记 | 纵向 | 现有笔记编辑器 |

普通滚轮只滚动所在内容，不跨文档联动。沿用现有阅读器的翻页/选区/复制快捷键，焦点在哪一篇，操作就属于哪一篇；输入框和编辑器中不捕获阅读导航键。按钮可通过 Tab、Enter/Space 操作，提示和错误不抢夺编辑器焦点。分界拖动复用现有受控尺寸与键盘调整约定，拖动时抑制 hover 重渲染；首版不增加跨工作区或系统级拖放契约。

## 7. 推荐数据模型

### 7.1 标签阅读状态

```ts
type TagMemberStatus = 'unread' | 'reading' | 'done' | 'skipped';

type TagMemberReadingState = {
  status: TagMemberStatus;
  order?: number;
  updatedAt: string;
};

type TagReadingWorkspace = {
  version: 1;
  revision: number;
  tagId: string;
  includeDescendants: boolean;
  activeEntryId?: string;
  compareEntryId?: string;
  queueCollapsed: boolean;
  splitRatio: number;
  memberStates: Record<string, TagMemberReadingState>;
  updatedAt: string;
};
```

### 7.2 不保存成员快照

`TagReadingWorkspace` 不保存权威 `memberEntryIds`。成员始终根据 Tag 关系实时推导，`memberStates` 只保存过程状态。

队列排序时：

1. 优先使用仍在成员集合中的显式 `order`；
2. 新加入且没有 `order` 的论文追加到队尾；
3. 已经移出的 Entry 状态作为孤立历史保留，但不参与渲染和进度；
4. 排序结果不能因刷新或任务状态变化自行重排；未显式排序的新成员用稳定的时间与 ID 次序追加；
5. 不自动定期清除历史进度。将来如增加清理，必须由用户明确触发并说明影响。

首版不预建 `views`、`cameraPairStart`、研究问题、综合笔记或多轮次字段。恢复时校验标签、成员、资源能力和数值范围；状态结构的 `version` 与写入冲突使用的 `revision` 含义不同。删除归档的元数据独立保存，不将已删除标签伪装为可编辑的活动工作区。

### 7.3 B2 综合笔记所有权（后续设计）

综合笔记不能虚假挂载到某一篇论文 Entry。建议把 Note 所有权泛化为：

```ts
type NoteOwner =
  | { kind: 'entry'; entryId: string }
  | { kind: 'tag-reading'; tagId: string };
```

标签综合笔记沿用现有 Markdown 编辑器、自动保存和 Source Link 能力。Source Link 的来源仍然是具体 `EntryId + SegmentUid + page`，因此同一篇综合笔记可以引用多篇论文。

该变化需要同步扩展 Note 与 Link owner 的领域类型、Workspace 布局、IPC 请求和前端类型。不要通过创建隐藏 Entry 来绕过所有权问题。

## 8. 状态与架构边界

### 8.1 状态所有者

- `App` 继续作为顶层 `WorkspaceSurfaceLayout`、tab、pane 和焦点的唯一所有者；
- 新增一种 `tag-reading` Workspace Surface，由 `tagId` 唯一标识；
- `TagReadingWorkspaceView` 负责标签队列、当前/对照角色、内部比例和响应式显示；不再拥有另一套外层 tab 或全局焦点；
- PDF、Reflow 和 Note 继续管理各自的纵向滚动、选择和编辑会话；
- 持久状态由 Workspace 服务写盘，React 状态只保存当前交互草稿和动画状态。

### 8.2 推荐模块

以下是拟新增边界，不代表当前已经存在：

```text
crates/neuink-domain/src/tag_reading.rs
crates/neuink-workspace/src/tag_reading.rs
crates/neuink-ipc/src/commands/tag_reading.rs

apps/desktop/src/modules/reader/parallel-reading/
  TagReadingWorkspaceView.tsx
  TagReadingQueue.tsx
  ReadingViewFrame.tsx
  useTagReadingWorkspace.ts
```

应优先复用：

- 现有 PDF/Reflow/Markdown Note 业务组件；
- `apps/desktop/src/components/ui` 中的 Button、ToggleGroup、DropdownMenu、Tooltip 等基础组件；
- `theme.css` 语义 token；
- `EntryReadingState` 与现有 reading-state IPC；
- 标签树及后代标签收集工具；
- 当前 Assistant tag scope 和跨 Entry Source Link。

不新增第三方 UI 或布局依赖。只增加该业务需要的 Surface 类型，不设计通用 Tab 插件注册系统。阅读数据加载、模式切换、页码保存和草稿保护必须复用现有所有者，避免复制一份 `ReaderPane` 或 `EntryWorkspaceView` 的编排逻辑。

### 8.3 写盘与恢复

- 标签阅读状态是用户数据，不放入可删除缓存；
- 单文件状态使用现有原子写策略；
- 写入携带基础 `revision`，由 Workspace 服务校验；并发更新串行化或冲突拒绝，不采用最后一次整文件覆盖。前端短周期提交状态并显示未保存/失败/重试，不能只在退出时保存；
- 首次读取失败或未知版本时禁止用默认空状态覆盖文件；迟到请求不得写入另一标签或另一资料库；
- 综合笔记正文与 Source Link sidecar 必须沿用冲突检测和一致性规则；
- 关闭应用、切换 Workspace、删除标签时必须先提交未保存状态；
- 状态 schema 带 `version`，读取时对未知版本返回可恢复错误，不静默覆盖。
- 标签删除前保存受影响的标签树、成员关系和阅读状态到可恢复归档，再通过 journal 或明确恢复协议执行多文件更改。当前直接删除逻辑必须纳入适配；归档失败时不继续删除。恢复使用原 TagId，不能新建同名标签冒充恢复；成员关系与当前编辑冲突时提示，不覆盖后来的标签修改。

## 9. Assistant 行为（B2/B3 及后续）

首版只复用已有 Assistant 能力，不新增自动总结或自动修改上下文的行为。后续适配：

进入标签平行阅读后，Assistant 的默认上下文按优先级组成：

1. 用户明确指定的当前/对照论文与选中 Segment；
2. 用户显式 `@` 的论文、标签和笔记；
3. 当前标签及后代标签内通过检索命中的其他论文；
4. 标签综合笔记。

不能把大标签中的全部 PDF Segment 无条件塞入上下文。标签只定义检索范围，实际证据仍通过搜索和显式选择确定。

AI 可以建议研究问题、对比维度和综合内容，但修改标签状态或综合笔记必须走现有 Proposal/Apply 边界。

## 10. 边界情况

### 10.1 标签变化

- 重命名标签：工作区继续存在，仅更新显示路径；
- 标签层级变化：成员按新的后代关系重新计算；这条兼容约束不代表当前已有“移动标签”操作；
- 删除标签：标签阅读状态和综合笔记先进入可恢复回收站，不直接永久删除；
- 删除父标签：其后代标签对应的阅读状态一并进入回收站；
- 当前正在阅读的 Entry 被移出标签：本次已打开视图保留到用户关闭，并显示“已移出当前标签”；进度立即从新成员集合重新计算。下次恢复只选择仍符合范围的论文，保留历史状态但不自动把移出的论文加回来。

### 10.2 Entry 与 PDF 变化

- Entry 进入回收站：从队列隐藏，打开视图进入不可编辑提示状态；
- PDF 内容 hash 变化：沿用 `EntryReadingState` 的文档变化处理，同时提示旧阅读位置可能失效；
- PDF 尚未解析：允许原文阅读，Reflow、Segment 引用和语义能力显示明确不可用状态；
- 同一 Entry 命中多个标签：只渲染一次，状态按当前标签工作区读取。
- 重新解析导致旧 Segment 失效：沿用已有重解析确认与来源失效提示，不静默丢弃笔记或把旧证据链接到新片段。

### 10.3 视图变化

- 取消对照：当前论文立即填满，不保留空白列；
- 有未保存的片段笔记或批注：保存失败时阻止受影响的切换/关闭；
- 只剩一个视图：占满可用空间；
- 没有可读论文：显示添加条目、选择其他标签或查看不可读原因的紧凑空状态；
- 当前/对照失效：不在编辑中突然卸载；恢复时清理无效显示引用，选择下一篇合法成员；
- 宽度暂时缩窄：只切换显示，不清除对照角色，也不将临时窄屏比例写回宽屏偏好。

## 11. 性能策略

- 首版最多两个活动阅读器，不预加载整个标签下的 PDF；队列读取轻量成员/状态摘要，不批量读取所有正文；
- 切换后非活动阅读器沿用已有缓存与脏内容保护策略，有未保存内容不卸载；
- 恢复时分别显示两篇的加载状态，一篇加载失败不遮蔽另一篇；
- 拖动分界线期间不触发高成本 HoverCard、原图快照生成和重复解析；
- 先测量真实 PDF 内存与切换延迟，再决定缓存上限，不提前引入新的虚拟化库。

真实检索、方向图和组会方案分别按开发计划 C/D 推进，不等同于 B1 完成。候选经用户选择才进入标签；区分有来源的引用、相似性和 AI 设想。离线/无检索权限不能影响本地阅读。

## 14. 本轮采用的产品决策

1. 默认包含后代标签，允许关闭；与当前资料库范围一致，但不把筛选结果另存为成员权威副本。
2. 跳过从任务分母排除并单独计数；实际阅读百分比与“已完成”不是一个指标。
3. 标签删除前归档阅读状态和恢复所需关系，后续综合笔记沿用同一生命周期；不把现有直接删除逻辑当成已支持恢复。
4. 一个标签只有一个持续工作区；不增加多轮次、Collection 或 Session。
5. 默认只打开当前论文，用户主动固定对照；综合笔记后置，不自动创建空稿。
6. 首版双篇独立滚动、容器级响应式；镜头轨道、证据表和研究发现按后续阶段实施。

## 15. 标签、笔记与阅读组织：最终修改意见稿

> 修订日期：2026-09-12。本节定义拟实施的最终行为，供产品与工程评审；本轮只修改方案文档。实现完成度仍以 [开发计划](../docs/development/dev-plan.md#516-标签详情标签笔记与条目阅读关联待实施2026-09-12) 为准。
>
> 涉及标签详情、标签笔记入口与首轮范围的旧表述，以本节为准；前文 B1 的阅读队列、固定对照、独立滚动和状态恢复契约继续适用。

### 15.1 产品目标

每个 Tag 可以表达一组论文及其研究主题，只需维护名称和一段可选描述，并拥有多篇标签笔记。一篇标签笔记可以引用多篇论文。用户从标签打开其中任意条目后，应能在原文旁找到并编辑这些标签笔记，也能根据来源筛选出引用当前论文的笔记。Tag 支持移入现有回收站并恢复。

标签详情、单篇阅读和平行阅读使用同一份笔记。标签笔记的创建、打开、保存和导出独立于平行阅读任务是否建立或加载成功；平行阅读只负责组合显示已有论文与笔记。

现有 Source Link 已能记录跨 Entry 的来源，本轮复用该能力。这里的“对齐多篇论文”指建立可追溯的引用和相关笔记关系；自动提取对比表、全文语义匹配和 AI 综合写作另行实施。

### 15.2 统一概念与归属

| 对象 | 定义 | 归属与约束 |
| --- | --- | --- |
| 标签 Tag | 论文组与研究主题，有名称、可选描述和父子层级 | 与 Entry 多对多关联；稳定 TagId 不随名称变化；支持移入回收站和恢复 |
| 条目 Entry | 一份资料及其内容，可没有主 PDF | 保留条目笔记、原文片段、片段笔记、批注及单篇阅读状态 |
| 文档笔记 Note | 有标题、正文、图片和来源链接的 Markdown 文档 | 每篇只有一个明确 owner；统一通过 NoteTarget 打开与编辑 |
| 条目笔记 | owner 为 Entry 的文档笔记 | 可引用其他条目；不因跨论文引用而自动改为标签笔记 |
| 标签笔记 | owner 为 Tag 的文档笔记 | 一个 Tag 可有多篇；允许引用多篇论文，也允许没有来源 |
| 片段笔记与批注 | 附着在原文片段或文本选择上的记录 | 保持原有 Entry/Segment 归属及编辑规则；通过片段记录入口访问 |
| 来源链接 Source Link | 笔记到原文证据的关系 | 携带来源 Entry、Segment、页码与快照；可据此反查相关笔记 |
| 平行阅读工作区 | 一个 Tag 对应的持续阅读任务与布局 | 保存队列、主读、对照、任务状态和打开的 NoteTarget；不拥有笔记正文 |

用户文案统一采用“文档笔记”作为总称、“条目笔记 / 标签笔记”表示归属。当前“标签综合笔记”统一显示为“标签笔记”；综合、摘录、研究问题等由标题和内容表达，无需再创建不同的笔记类型。

“归属”“引用”“阅读上下文”分别管理：

- 笔记归属决定管理位置和删除恢复边界。
- 来源决定笔记引用了哪些论文及具体片段，可推导相关性。
- 阅读上下文决定此刻优先展示哪个 Tag 的论文和笔记，不修改数据归属。
- 本轮保留 Entry、Tag 两种文档笔记归属；不引入额外 Collection、用户维护的阅读 Session 或多 owner 笔记。

### 15.3 标签详情与描述编辑

每个标签提供独立“标签详情”，默认进入标签概览。侧栏选择标签继续沿用现有筛选行为；在标签页面标题区和标签对象菜单提供明确的“打开标签详情”，不把树形展开动作改成详情导航。

标签详情共用一个 Tag 上下文，提供以下内容入口：

| 入口 | 内容与主要操作 |
| --- | --- |
| 标签概览 | 查看名称、完整路径和描述，编辑描述，开始或继续平行阅读 |
| 标签论文 | 复用现有条目库列表，显示直属或含后代论文，打开条目 |
| 标签笔记 | 管理该标签拥有的笔记，创建、搜索标题、打开、软删除和恢复 |
| 平行阅读 | 打开该标签现有阅读工作区，恢复原有主读、对照与任务状态 |

用户只需维护名称和描述。名称复用既有重命名操作；描述是可选多行文本，用于说明论文组的范围或用途，可以留空。关键词、别名和独立研究问题字段从本方案移除，相关想法直接写入描述或标签笔记。

完整路径根据现有层级派生显示，结构调整仍由标签管理负责。概览通过“编辑描述”进入一个文本编辑区，提供“保存 / 取消”；保存失败保留输入，离开未保存编辑时沿用统一草稿保护。

只在论文和笔记入口或列表显示相应数量，不增加独立统计面板。论文列表注明直属或含后代范围；标签笔记数只统计当前 Tag 直接拥有的未删除笔记。阅读任务进度沿用平行阅读中的展示。数量从权威数据派生，加载或失败不能显示为最终的零，也不能禁用描述编辑和笔记入口。

### 15.4 标签笔记管理

- 标签笔记列表只展示当前 Tag 拥有的笔记；子标签笔记在其自己的标签详情中管理。
- 采用紧凑列表，默认按更新时间倒序并支持标题筛选，展示标题、更新时间和已引用论文数。论文数按来源 EntryId 去重，不把同篇论文的多个片段计成多篇。
- 点击笔记可以独立打开，也可以在分屏中打开；无需先进入平行阅读。
- 从标签详情新建时默认且明确归属当前 Tag。输入标题并提交后才创建，不在打开标签或空状态时自动生成空文件。
- 在条目或平行阅读的混合选择器中新建时，明确区分“新建条目笔记”和“新建标签笔记”，展示将归属的对象名称。
- 保留现有图片、自动保存、来源预览和定位、Markdown 另存为、Word/TXT 导出及软删除恢复能力。
- 关闭笔记只关闭视图；在其他入口再次打开时仍是相同 NoteId。过滤条件变化不能自动关闭当前编辑中的笔记。

### 15.5 从条目阅读和编辑标签笔记

普通条目阅读页和标签平行阅读均接入同一套笔记选择与编辑能力。笔记区域区分“条目笔记”和“标签笔记”；前者默认管理当前条目的笔记，后者根据阅读上下文展示标签笔记。

**从某个 Tag 进入条目时：**

1. 保留进入时的 Tag 作为当前研究上下文，在笔记区域显示标签名称及可查看的完整路径。
2. 标签笔记默认展示“当前标签全部笔记”，使用户能够继续撰写尚未插入来源的想法。
3. 提供“引用本论文”筛选，根据已保存来源筛选当前标签笔记，并标出相关论文及引用位置。
4. 所有未删除标签笔记都可以打开、编辑；有没有引用当前论文只影响筛选和定位，不决定编辑资格。
5. 选择笔记后，复用原编辑器在原文旁编辑；不同入口修改同一份文档，继续遵守唯一编辑所有者规则。

**直接从全部条目、搜索或其他无 Tag 上下文的入口打开时：**

- 标签笔记区域默认展示“引用本论文的标签笔记”，按所属 Tag 分组，不擅自挑选某个标签作为当前主题。
- 提供标签选择器，可选择条目的直属标签或按既有后代规则包含该条目的祖先标签，查看那个标签的全部笔记。
- 其他 Tag 拥有、但确实引用本论文的笔记也可通过反向引用打开；始终展示真实归属，不自动把论文加入那个 Tag。
- 没有相关引用时显示明确空状态，并保留选择标签、打开标签详情或创建适当归属笔记的入口。

Tag 上下文属于当前阅读视图的导航状态，不写入 EntryMeta，不改变 NoteOwner，也不作为条目或笔记的身份。用户从另一 Tag 再次打开已存在的同一条目时，复用现有页面并更新其上下文；只改变列表范围时保持编辑器实例，确需替换编辑器时检查受影响的草稿。

### 15.6 多论文来源与反向关联

正式的“引用本论文”集合由已保存笔记的有效来源推导：

```text
某篇笔记引用的论文集合 = 已保存正文实际使用的 Source Link 中，sources.entry_id 的去重集合
当前标签的相关笔记 = owner 为当前 Tag，且来源包含当前 Entry 的未删除笔记
某篇论文的标签反向引用 = 来源包含当前 Entry 的所有未删除标签笔记，按 owner Tag 分组
```

来源关联规则：

- 同一笔记可以保存来自 A、B、C 等多篇论文的来源。条目笔记和标签笔记都复用此能力。
- 展示实际引用的论文、片段、物理页码和快照；同一篇笔记在笔记列表只出现一次，多个引用位置在详情中展开。
- 从反向引用打开笔记时可以携带 anchorId 定位到对应引用位置；它是导航请求，不改变 NoteTarget 身份。
- 来源必须是正文实际使用的有效引用；未使用 sidecar 项、普通文字提到论文名称、代码中的字面量 token 不算正式关联。
- 正常查询只纳入所属标签未进入回收站且笔记未删除的文档；回收站中的内容保留，恢复原标签后重新纳入查询。
- 保存成功后更新反向查询结果；未保存或保存失败的草稿不作为已保存关联发布。
- 移除最后一个指向 A 的有效来源并保存后，该笔记退出 A 的“引用本论文”集合，但仍存在于所属标签的全部笔记中。
- 允许打开没有引用当前论文的标签笔记，也允许引用标签成员之外的论文。引用不会自动修改标签成员、笔记归属或阅读完成状态。
- 当前编辑的笔记因来源变化退出筛选结果时，保留编辑视图，提示它已不符合筛选，而不是立即卸载。
- 来源跳转允许打开标签外论文，保留笔记与返回路径，不为跳转临时修改标签成员。

首轮采用可解释的来源关系。无精确引文的笔记仍可从标签全部列表访问；人工关联论文、基于正文的语义相关性等可后续扩展，届时分别显示关系类型，不能伪装成精确引用。

### 15.7 平行阅读的职责收敛

平行阅读负责论文队列、主读与固定对照、阅读任务状态、区域切换和布局恢复。单篇页码、实际阅读时长继续由 EntryReadingState 管理，同一论文在不同标签下仍可有不同任务状态。

笔记能力改为调用通用笔记服务与编辑器：

- 平行阅读保存的 active_note 仅为 NoteTarget 引用，关闭阅读任务不会删除或改变笔记。
- 选择器按“当前标签笔记 / 成员条目笔记”分组，复用来源筛选与归属标识，不另做一套笔记管理逻辑。
- 保留现有主读加笔记、主读加对照的两栏组合及窄屏切换；不扩大为同时渲染大量论文的布局。
- 标签阅读进度加载失败、保存失败或队列不可用时，独立笔记入口仍可管理正常的标签笔记。
- 没有可读 PDF 或解析内容的标签，也能先填写描述和撰写标签笔记。

### 15.8 状态隔离与必要保护

各对象分别持有加载、保存和错误状态，不将阅读进度、标签描述和所有笔记合成为一个全局 disabled。

| 操作或失败 | 影响范围与处理 |
| --- | --- |
| 切换笔记列表筛选或 Tag 上下文 | 不替换编辑器时直接更新列表，保持当前草稿 |
| 更换当前笔记 | 只检查被替换或失去保留能力的笔记编辑器 |
| 更换主读论文或阅读模式 | 检查实际会卸载的原文、片段笔记和批注编辑器；保留不受影响的文档笔记 |
| 修改任务状态、队列顺序或布局 | 沿用阅读状态自己的保存边界；未卸载编辑器时不要求保存无关笔记 |
| 关闭整个阅读工作区、退出或切换资料库 | 聚合受影响的全部草稿，保存后复查；失败时保留页面 |
| 单篇笔记保存失败或文件损坏 | 局部显示错误和重试，保留可恢复草稿；其余笔记、标签描述和阅读功能仍可使用 |
| 统计或阅读进度失败 | 局部显示失败状态，不禁用正常的笔记管理 |
| 同一笔记从不同入口打开 | 共享文档身份和编辑权；一个编辑所有者，其他视图只读，可显式接管 |
| 插入来源时切换了目标或资料库 | 校验实际 NoteTarget、资料库和编辑权；迟到响应不得写错对象；只改变 Tag 上下文且目标不变时不误判为更换笔记 |

保留 revision 冲突检测、加载失败只读、保存期间新输入保护、正文与来源一致性以及路径校验。来源插入目标必须是当前可编辑且可见，或本次操作明确打开的笔记；不向隐藏旧目标自动写入。

PDF、重排和来源引用分别检查所需的真实资源。没有有效片段时仍允许普通文档笔记编辑；仅有有效解析结果的条目仍可引用。解析任务状态与资源可用性需要统一核查：有经过验证的旧片段时避免只因任务失败禁用全部引用；原文替换、片段失效或版本不匹配仍需明确提示并阻止错误定位，保留原有证据快照。

### 15.9 Tag 回收站、恢复与成员变化

用户操作统一为“移到回收站 / 恢复标签”，底层复用现有 TagArchive 与多文件恢复事务。现有回收站的全部列表可见标签项目，并增加标签类型筛选；“标签管理 → 已删除标签”改为跳转这个列表，不另建第二套回收站或归档状态。

**移入与展示：**

- 标签菜单和详情菜单提供“移到回收站”。确认说明将影响哪些子标签和标签笔记，并明确组内论文及条目笔记继续保留在资料库。
- 父标签及其现有子标签作为一组进入回收站，保留原 TagId、名称、描述、成员关联恢复快照、标签笔记及阅读状态。每组在回收站显示一条标签项目，展示根标签、删除时间和子标签数，不把每个子项重复计算为独立删除事件。
- 标签从活动树和正常选择器中移除，受影响论文解除这些标签关联；其他标签关联不变。论文文件、条目笔记、片段笔记和批注不随标签移入回收站。
- 随标签进入回收站的标签笔记暂停正常编辑和反向引用展示，正文、来源、图片和原有删除标记均保留。独立页面和阅读区不得继续以旧状态写入这些笔记。
- 移入前检查该标签及后代标签的描述草稿、独立标签笔记和嵌入阅读区草稿。只处理受影响对象；保存失败或用户取消时不执行移入。

**恢复：**

- 恢复一组标签时使用原 TagId 和 NoteId，恢复原有层级、描述、笔记可访问性、阅读状态及可安全恢复的成员关联。
- 原先已单独删除的标签笔记仍保持已删除；恢复标签不等于恢复它下面所有曾删除的笔记。
- 复用现有同名、父标签缺失、关联被后续修改等冲突检查，给出原因并保留回收站记录，不覆盖当前资料；已经永久删除的论文不重建。
- 首轮标签项目提供移入和恢复。现有永久删除/清空逻辑只处理其已支持的条目与记录类型，按钮、计数和确认文案明确限定该范围，不能把不包含标签的操作称为“清空全部回收站”。标签永久删除不借接入列表隐式执行。

**其他生命周期：**

- 单独删除标签笔记继续复用既有软删除和恢复；保留正文、来源和图片，恢复原 NoteId。删除后从正常列表与反向引用中移除，并关闭或转为不可编辑的旧视图。
- 从标签移除论文只改变成员集合与相应阅读统计；已有标签笔记和来源不删除，阅读历史按原有规则保留。
- 删除来源论文保留标签笔记及原文快照，来源显示不可用；恢复论文后重新核查可定位性。不能因一篇来源不可用而禁止整篇标签笔记编辑。
- 标签重命名更新显示名称和路径，不修改文档身份。祖先包含后代的论文范围与各标签独立拥有的笔记范围继续分别计算。

### 15.10 代码与数据修改边界

| 层次 | 需要修改的内容 |
| --- | --- |
| Domain | 只为 TagMeta 增加 description 字符串，默认空；不增加 details 对象和额外主题字段；保留 NoteOwner / NoteTarget 和来源模型 |
| Workspace / IPC | 在既有标签元数据写盘边界增加描述更新；统一按 NoteTarget 访问笔记、查询标签笔记及来源反向引用 |
| 通用笔记能力 | 从平行阅读中提取可复用的笔记列表、选择、打开、创建与异步管理；继续复用 MarkdownNoteEditor、图片、来源和导出实现 |
| Surface 与导航 | 增加标签详情页面；通用 note 页面按 NoteTarget 打开；条目页面携带可选 Tag 导航上下文 |
| 反向来源 | 收集 Entry-owned 和 Tag-owned 笔记；反向引用目标使用 NoteTarget，替换只接受 noteEntryId 的假设 |
| 阅读页面 | 普通 PDF/Reflow 与平行阅读共用标签笔记入口、来源筛选和明确的插入目标 |
| 回收站 | 将既有 TagArchive 接入统一列表与恢复入口；类型化区分标签项目和条目记录，标签恢复按 archive_id 分派，不伪造 EntryId |
| 编辑安全 | 按实际受影响对象确定草稿范围；Tag 移入回收站覆盖新增独立页面和描述编辑会话 |

兼容与持久化要求：

- description 缺失的旧 Tag 按空描述读取。描述更新只写目标标签的 description 和必要时间信息，校验描述基础 revision，不以整份旧标签列表覆盖其他修改。
- 标签移入回收站、恢复、重命名及现有元数据更新路径必须保留 description；旧 TagArchive 记录仍可读取。
- 保留现有条目笔记格式、标签笔记 Markdown/frontmatter 和 tag-reading 目录，本轮不进行批量路径迁移。
- 保留 NoteOwner 中 tag_reading 的既有序列化值作为兼容协议；对用户和业务表达其 Tag 归属，笔记服务不依赖阅读任务状态。
- 旧 note 页面描述中的 entryId + noteId 读取为 Entry-owned NoteTarget；不通过清空布局来完成升级。
- 文档身份统一由资料库、owner 类型与 ID、NoteId 确定。Tag 上下文和编辑会话 ID 不参与内容归属；适配层外不把标签标识当作真实 EntryId 使用。
- 来源反向关系属于可重建查询数据，复用现有读取和缓存能力；如需持久化索引，放入 .neuink-cache，依据权威笔记文件与有效来源重建。不得把反向查询结果另写成 Entry 或 Tag 的权威成员关系。
- 保存、删除、恢复后更新索引；刷新或重新打开资料库时检查文件指纹。首轮不承诺多个独立进程同时编辑同一资料库的实时同步。
- 列表查询优先读摘要并复用缓存，打开笔记时再载入编辑正文，避免每次选中条目都重新读取全库笔记和 PDF。

### 15.11 界面复用与交互契约

- 标签详情复用现有内容导航、信息展示、条目列表、Tag 控件和 shared UI；使用 theme.css 语义 token，不新增装饰性卡片网格。
- 描述编辑、笔记查询、文档编辑和阅读任务分别管理状态；页面可聚合展示，但不复制多份数据权威。
- 标签列表、笔记列表、原文和编辑正文在各自区域承担滚动；固定工具栏不参与正文滚动，不叠加页面级双滚动条。
- 来源定位不无条件抢走输入焦点；切换筛选和统计刷新不重挂载编辑器。
- 复用现有分屏、键盘、拖动和焦点契约；新入口支持键盘访问，关闭弹窗返回触发点。
- 使用现有已安装依赖；若实施中确需增加依赖，按项目 UI 规范单独说明必要性。

### 15.12 首轮实施范围与顺序

首轮必须完成“编辑 Tag 描述 → 管理多篇标签笔记 → 引用多篇论文 → 从单篇论文找到并编辑相关标签笔记”的完整用户流程，并接通 Tag 移入统一回收站和恢复。反向来源与普通条目阅读入口属于首轮必做，不能再次推迟到仅完成标签详情之后。

1. 增加标签 description 及更新接口，完成旧资料库和 TagArchive 兼容；统一笔记目标与页面身份。
2. 建立标签详情及笔记列表入口，独立打开、创建、编辑、删除和恢复标签笔记，接通 Tag 回收站列表与恢复入口。
3. 扩展通用笔记目录与反向来源查询，接入条目阅读上下文、全部标签笔记和“引用本论文”筛选。
4. 平行阅读改为复用上述能力，拆分禁用状态与草稿保护范围，验证独立和嵌入两种打开方式。
5. 完成端到端验收，并将稳定产品规则、实际架构和实现状态分别同步到 PRD、系统架构和开发计划。

后续可扩展全局全文/语义搜索对标签笔记的覆盖、人工论文关联、Assistant 附件与受控 Proposal、证据对比表和研究图；这些功能不作为首轮用户流程的前置条件。笔记选择器的标题筛选和上述来源反向查询包含在首轮范围内。

### 15.13 验收标准

使用标签 T、论文 A/B/C、标签笔记 N1/N2/N3 作为固定验收样例：N1 引用 A/B，N2 引用 B/C，N3 尚无来源。

- [ ] T 只维护名称和可选描述；描述修改后重开仍保留，留空合法，旧资料库缺少 description 时可正常打开。
- [ ] T 下可创建多篇标签笔记；即使没有论文、没有可读资源或未进入平行阅读，也能写笔记。
- [ ] 标签详情的笔记列表显示 N1/N2/N3，按稳定归属展示；包含后代论文时不混入子标签拥有的笔记。
- [ ] N1 保存后保留 A/B 的来源与准确页码/快照，可分别定位；现有 Word/TXT 导出仍含两篇论文的可读证据。
- [ ] 从 T 打开 A，默认可查看并编辑 N1/N2/N3；“引用本论文”只显示 N1，且同一笔记不因多个来源重复出现。
- [ ] 打开 B 时相关笔记为 N1/N2；直接从全库打开时按所属 Tag 分组，条目存在多个标签也不会自动选错上下文。
- [ ] N3 可以在阅读 A 时编辑并插入 A 的来源，保存后进入相关集合；没有来源不会阻止打开或编辑。
- [ ] 删除 N1 对 A 的最后一个来源并保存后，它退出 A 的引用筛选，仍保留在 T 的全部笔记中，当前编辑器不突然关闭。
- [ ] 标签详情、普通分屏和平行阅读打开 N1 时使用同一文档身份；编辑接管、只读和保存冲突保护有效。
- [ ] 切换筛选、Tag 上下文和不卸载编辑器的任务操作不要求保存无关草稿；关闭整个工作区或切换资料库仍检查全部受影响内容。
- [ ] 阅读进度失败不阻止正常笔记操作；一篇笔记失败不阻止其他笔记；保存期间新增输入不丢失，迟到来源不写入其他目标。
- [ ] 删除来源论文保留标签笔记与快照；移除标签成员不删除笔记。
- [ ] T 可从菜单移入现有回收站，在全部列表和标签筛选下可见，恢复入口共用现有 TagArchive；活动标签树不再显示 T。
- [ ] 移入父标签连同子标签及其标签笔记保留，组内论文、条目笔记及其他标签关系不删除；回收站按一次操作显示一组。
- [ ] 恢复标签保留名称、描述、原层级、笔记、阅读状态和稳定 ID；先前单独删除的笔记仍保持已删除；恢复冲突不覆盖后续修改。
- [ ] Tag 移入回收站时能够发现独立标签笔记页面和描述编辑区的未保存修改，保存失败不继续操作，完成后旧视图不可继续写入。
- [ ] 回收站中的标签项目不会落入现有按 EntryId 执行的永久删除分支；清空按钮和确认文案准确表示实际支持的类型与数量。
- [ ] 缓存删除后可从真实文档重建反向关系，刷新可识别文件变化；已删除笔记与未使用的来源不进入正常查询。
- [ ] 正常、加载、空、错误、只读状态，以及键盘、滚动、现有分屏拖动、窄容器、100%/125% 缩放均完成相关验证。
- [ ] 运行与改动相称的 Rust 行为测试、TypeScript 检查和前端测试；原生 Tauri/WebView2 视觉与实际文件操作单独验收，未完成项明确报告。
